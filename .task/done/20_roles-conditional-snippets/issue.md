# 20 — roles: условные сниппеты и стандартный движок шаблонов

## Контекст

Расширение `extensions/roles` собирает текст роли из markdown-источников:
`roles/<роль>.md` содержит директивы `@<файл>.md` (`@tests.md`,
`@interview_discipline.md`), `expandRefs` (extensions/roles/materialize.ts)
подставляет содержимое файла из `roles/` или её подкаталога, результат
пишется в `roles/materialized/<роль>.md` и уходит в system prompt.

@NikolayXHD хочет два изменения.

**Динамическая подстановка.** Поведение моделей различается: правило, которое
текущая модель соблюдает нативно, в промпте лишнее. Включением сниппета должен
управлять флаг; имя флага совпадает с именем сниппета; флаг не задан —
подстановка пустая. Набор флагов пользователь выбирает вручную.

**Стандартный движок.** Механизм подстановки сейчас самописный
(`resolveRefPath` + `expandRefs`); хочется проверенный временем готовый.

## Находки

- `roles/materialized/*.md` версионируются в git и служат точкой наблюдения
  за тем, что реально попадает в контекст (design.md задачи 18). Если флаги
  приходят из командной строки запуска, содержимое materialized начинает
  зависеть от того, как запущен pi, и перестаёт быть воспроизводимым.
- `make materialize` (extensions/roles/Makefile) запускает материализацию
  без процесса pi, поэтому регистрируемые расширением CLI-флаги ему
  недоступны.
- «Флага нет — подстановка пустая» в буквальном прочтении делает условными
  все сниппеты, включая те, что нужны всегда (`task_tracking`, `tests`).
- Текущий `expandRefs` при нерешённом пути оставляет директиву в тексте как
  есть: опечатка в имени сниппета не видна ни пользователю, ни тестам.
