## Исправлено

- **F1 (P0):** рецепт разбора оборванной подмены дерева был неполон.
  Теперь начало прохода разбирает все три состояния: остатки черновика
  удаляются; если есть и `materialized/`, и `previous/` — `previous`
  удаляется как вытесненное дерево; если `materialized/` нет, а
  `previous/` есть — он возвращается на место; при подмене старое дерево
  переименовывается только если оно есть. Иначе `rename` в занятый
  каталог падал бы (ENOTEMPTY) и проход зависал бы навсегда.
- **F2 (P1):** задан базовый уровень: если предыдущего успешного
  состояния нет (старт сессии, resume), свежий вариант не собран —
  роль не применена, записи сессии и события нет. Для resume: имя
  активной роли берётся из записи сессии, вариант пересчитывается
  по текущей области, текст по записанному `path` не восстанавливается
  (см. интервью, пункт 25); шапка `index.ts` описывается так же.
- **F3:** при битом конфиге `/role` перечисляет роли, но применить
  не может — выбранная роль остаётся прежней, Tab в меню не срабатывает.
- **F4:** память о предупреждениях сбрасывается не только на
  `session_start`, но и при принятии нового снапшота: «исправил и сломал
  снова» снова даёт сигнал.
- **F5:** «Миграция» перечисляет сценарии с изменившейся семантикой
  (неизвестные ключи — ошибка, заготовка вместо `{}`, плоских рендеров
  нет, роль при битом конфиге не сбрасывается); шаг 7 плана на них
  ссылается.
- **F6:** сигнатура `loadConfig` — `Config | { problem: string }`.
- **F7:** предупреждение о провале рендера называет запись, роль
  и файл.
- **F8:** знак `+` не поддержан; значение с ним — ошибка конфига.
- **F9:** из «Проверки» убран кейс про снятие роли, механизма для него
  нет; вместо него — «свежий вариант не получен на старте сессии».
- **F10:** уточнены формулировки: плоские рендеры исчезают при первой
