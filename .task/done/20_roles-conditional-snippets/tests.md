# Тесты: условные сниппеты ролей

Дизайн тестового покрытия. Написание тестов — отдельный шаг после
согласования кейсов.

## Стенд

- `probe.mjs` — сценарный прогон без фреймворка, как было: фикстура
  во временном каталоге, строка `ok — имя` на успех, `FAIL — имя`
  и счётчик провалов на ошибку.
- Автоматически проверяются `config.ts`, `render.ts` и `materialize.ts`.
  `index.ts` probe не грузит: он импортирует
  `@earendil-works/pi-coding-agent`, которого нет в `node_modules`
  расширения; сессионные сценарии — вручную по `TESTING.md`.
- Подварианты одного сценария — один табличный/параметризованный
  сценарий, а не россыпь кейсов; имена сценариев по шаблону
  `when_..._then_...`.
- `TESTING.md` переписывается под ручные сценарии ниже: текущий текст
  описывает прежнюю семантику (плоские рендеры, заготовка `{}`,
  сохранение незнакомых ключей).

## `config.ts`

1. `when_no_roles_json_then_stub` — заготовка: одна запись `default`,
   пустая область, пустые флаги.
2. `when_valid_config_then_all_fields` — `default`, `cycle` и две записи:
   разобраны `startRole`, `cycle`, имена, модели, уровни, флаги.
3. `when_no_top_level_default_then_valid` — ключа `default` нет,
   конфиг разобран, `startRole` отсутствует; запись `default`
   при этом обязательна (см. таблицу ниже).
4. `when_config_rejected_then_problem` — таблица входов, один ожидаемый
   вердикт «отвергнут»:
   не JSON; не объект; неизвестный ключ; пустое имя ключа; `default`
   не строка; `default` пустая строка; `cycle` не массив строк; нет
   ключа `template_variables`; `template_variables` не массив; запись
   не объект; неизвестный ключ записи; имя записи не по `[A-Za-z0-9_-]`;
   дубликат имени; нет `scope`; `scope` не объект; неизвестный ключ
   `scope`; нет `flags`; `flags` не массив; элемент списка не строка;
   пустое значение; знак `+`; лишний `-`; смесь знаков; неизвестный
   уровень; нет записи `default`; у записи `default` непустая область.
5. `when_entry_flags_then_values` — таблица: пустой список — истина
   любому имени; положительный — истина только перечисленным;
   отрицательный — истина всем, кроме перечисленных.
6. `when_pair_matches_then_entries` — таблица: запись `default`
   в результат не входит; модель с положительным списком; модель
   с отрицательным; уровень; составной ключ `provider/id`, где `id`
   содержит слэш.
7. `when_model_unknown_then_reported` — таблица: неизвестная ссылка
   в отчёте вместе с именем записи; знак `-` снят; известная ссылка
   в отчёт не попадает.
8. `when_config_round_trip_then_equal` — после `serializeConfig`
   и повторного разбора конфиг тот же.

## `render.ts`

9. `when_snippet_dir_listed_then_files_only` — обычные файлы читаются,
   подкаталоги и имена с точки пропускаются.
10. `when_sections_collected_then_names` — обычные и инверсные секции,
    вложенные секции; интерполяции не собираются.
11. `when_template_rendered_then_output` — таблица: `{{> x}}`
    подставляет содержимое; отсутствующий partial даёт пусто;
    выключенное имя — ложь (обычная секция не рендерится, инверсная
    рендерится); `{{! }}` не выводится; `{{имя}}` печатает `true`;
    `{{#tests.md}}` не рендерится, даже если плоский ключ `tests.md`
    в view есть; `{{> constructor}}` при пустом словаре даёт пусто
    и не зовёт унаследованный конструктор.
12. `when_at_directive_then_literal` — строка `@x.md` в шаблоне
    остаётся как есть: поддержки `@` не осталось.

## `materialize.ts`

13. `when_no_roles_json_then_stub_and_tree` — файл создан с записью
    `default` и `cycle` из ролей каталога; дерево —
    `materialized/default/`.
14. `when_two_entries_then_dirs_and_gates` — у каждой записи свой
    каталог; вариант с выключенным сниппетом его текста не содержит;
    плоских файлов нет.
15. `when_template_broken_then_tree_unchanged` — незакрытая секция:
    предупреждение с записью, ролью и файлом; содержимое дерева то же;
    черновика не осталось.
16. `when_partial_cycle_then_tree_unchanged` — `{{> a}}` ↔ `{{> b}}`:
    ожидание то же, что в 15 (`RangeError`).
17. `when_config_broken_then_tree_unchanged` — конфиг отвергнут:
    предупреждение; каталоги и файлы `materialized/` не меняются.
18. `when_config_broken_and_swap_torn_then_recovery` — конфиг битый
    и остался `materialized.previous/`: остатки подмены разбираются,
    дерево вариантов при этом не меняется (уточняет «ничего
    не удаляет» из 17).
19. `when_snippet_name_equals_section_then_warning` — файл сниппета
    `verbose` и секция `{{#verbose}}` в роли: предупреждение с именем
    `verbose`, рендер успешен; негатив — файл `a` и секция `{{#b}}`
    предупреждения не дают.
20. `when_section_only_in_snippet_then_default_true` — имя секции
    встречается только во включённом сниппете: секция рендерится;
    запись с `-имя` её выключает.
21. `when_view_built_then_no_prototype` — секция `{{#constructor}}`
    и инверсная ей ничего не берут из прототипа: первый вариант
    не рендерится, второй рендерится.
22. `when_cycle_modes_then_names` — таблица `resolveCycle`: ключа нет —
    все роли; `[]` — пусто; только исключения — все, кроме; включения —
    только они, про неработающие исключения предупреждение; имена
    без файлов пропускаются.
23. `when_set_cycle_membership_then_mode_preserved` — таблица переходов:
    ключа нет — появляется `-имя`; `[]` — `[имя]`; список включений —
    дописать или убрать имя; список исключений — убрать `-имя`
    (когда ушло последнее, ключ пропадает) или дописать `-имя`;
    когда членство уже такое, файл не переписывается.
24. `when_new_role_then_appended_by_mode` — новая роль дописывается
    в конец по алфавиту в список включений и в `[]`; в список одних
    исключений не дописывается.
25. `when_role_removed_from_cycle_then_kept_out` — убранную из `cycle`
    роль следующий проход не возвращает: маркер — файл роли
    в каталоге записи.
26. `when_role_file_missing_then_exclusion` — пропавший файл роли
    превращается в `-имя`.
27. `when_tree_dirty_then_replaced` — заранее положенные плоский
    `materialized/old.md` и каталог удалённой записи после успешного
    прохода отсутствуют.
28. `when_swap_torn_then_recovered` — таблица: есть `materialized`
    и `previous` — `previous` удаляется; есть только `previous` —
    дерево восстанавливается; остатки `draft` удаляются.

## Вручную (`TESTING.md`)

29. Старт сессии: роль из `default`, флаг `--role`, resume возвращает
    роль сессии; статус `role:<имя>`; на старте без предыдущего
    состояния при неудаче роль не применена и события нет.
30. `before_agent_start`: текст роли дописан к промпту; смена модели
    переключает запись; битый конфиг оставляет прежний текст;
    отсутствующий файл варианта и конфликт записей — предупреждение,
    состояние прежнее; неизвестная модель — предупреждение, конфиг
    годен; отсутствие модели или уровня — ошибка расширения.
31. Горячее применение: правка `roles.json`, роли и сниппета действует
    к следующему ходу без `/reload`; битый конфиг не сдвигает снапшот,
    поэтому починка применяется; «исправил и сломал снова» —
    предупреждение показывается снова.
32. Событие `roles:active` и запись сессии `role`: `{name, entry, path}`
    при применении и смене варианта; при провале события нет
    и состояние прежнее.
33. Ctrl+R листает `cycle`; `/role` открывает меню, Tab правит список;
    при битом конфиге Ctrl+R молчит, `/role` перечисляет роли,
    но не применяет, Tab не работает.
34. Импорт mustache под загрузчиком pi — на старте сессии: роль
    рендерится, ошибок загрузки расширения нет.
