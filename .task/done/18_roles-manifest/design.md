# 18 — Дизайн: roles.json

## Цель

У расширения `roles` две жёсткие привязки: стартовая роль зашита в код
(`DEFAULT_ROLE = "develop"` в `extensions/roles/index.ts`), а Ctrl+R листает
все роли каталога.

Манифест `~/.pi/agent/roles.json` задаёт обе настройки: `default` — роль
старта, `cycle` — набор и порядок обхода. `materializeAll` поддерживает
`cycle` в согласии с каталогом ролей.

## 4.1. AS-IS

`extensions/roles/materialize.ts` раскрывает `@<файл>.md`-директивы в тексте
роли и пишет результат в `roles/materialized/<имя>.md` из `roles/<имя>.md`;
файл переписывается только при изменении содержимого. `materializeAll`
обходит каталог и материализует все роли, `materializeOne` — одну.
`materializeAll` запускается и из расширения, и из CLI: `make materialize`
вызывает `node materialize.ts <agentDir>`. Каталог `roles/materialized/`
лежит в git вместе с источниками.

`extensions/roles/index.ts` на старте сессии материализует все роли, затем
активирует роль: восстановленную из сессии (`reload`/`resume`), иначе из
флага `--role`, иначе константу `DEFAULT_ROLE`. Активация — `materializeOne`,
чтение `roles/materialized/<имя>.md` и запись текста роли в конец system
prompt на `before_agent_start`; имя роли объявляется в шине `roles:active`,
пишется в сессию (`appendEntry`) и в статусную строку. Ctrl+R переключает
роли, `/role <имя>` переключает явно, `/role` без аргумента и автодополнение
перечисляют всё, что нашлось в `roles/*.md` (`listRoleNames`).

Обновление списка встраивается в начало `materializeAll`: там уже происходит
обход каталога, которого оно требует.

## 4.2. Решения

### Манифест

`~/.pi/agent/roles.json` рядом с каталогом ролей:

```json
{
  "default": "preflight",
  "cycle": ["design", "preflight", "develop"]
}
```

`default` — имя роли, с которой стартует сессия без флага `--role`.
Необязателен: без него сессия начинается без роли.

`cycle` — записи для Ctrl+R. Обычная запись (`design`) — включение, запись с
минусом (`-datascience`) — исключение. Необязателен.

Файл версионируется в git и правится человеком; `materialize` меняет только
`cycle`.

### Режимы `cycle`

- Ключа нет — листаются все роли каталога по алфавиту.
- `[]` — не листается ничего.
- Есть хотя бы одно включение — листаются только включения в указанном
  порядке; исключения в таком списке не работают, о них выводится
  предупреждение.
- Только исключения — листаются все роли, кроме исключённых.
- Имена без файлов пропускаются.
- Если кандидатов не осталось, Ctrl+R ничего не делает.

### Поведение расширения

Стартовая роль разрешается в прежнем порядке: `reload`/`resume` → запись
сессии, иначе `--role`, иначе `default`. Если роли нет, сессия стартует без
неё, и это не ошибка.

Ctrl+R листает кандидатов по правилам выше; если активной роли среди них нет,
цикл начинается с первой записи. Пустой список кандидатов — нажатие ничего не
делает.

`/role <имя>` и `--role` активируют любую роль каталога, независимо от
`cycle`. `/role` без аргумента открывает меню: все роли по алфавиту, курсор на
текущей роли, роли из `cycle` обычным цветом, выключенные — приглушённым;
Tab включает и выключает роль, Enter активирует, Esc закрывает.
Автодополнение работает по всем ролям.

Вне TUI меню недоступно: RPC-режим получает обычный селектор, без диалогового
UI (print, JSON) выводится список в notify.

Активация только читает: текст роли берётся из `roles/materialized/<имя>.md`.
Материализацию — раскрытие сниппетов и запись файлов — делает исключительно
`materializeAll`: на старте сессии, по `/reload` и в `make materialize`. Роль,
созданную в открытой сессии, `/reload` делает материализованной и доступной.

Не меняются: дописывание роли в system prompt, событие `roles:active`, запись
роли в сессию, статусная строка, отсутствие роли в субагент-процессах.

### Обновление списка

Новая роль — файл `roles/<имя>.md`, имени которого нет в `cycle` ни как
`имя`, ни как `-имя`, и у которого нет `roles/materialized/<имя>.md`. Наличие
материализованного файла означает, что роль уже проходила материализацию;
поэтому роль, вычеркнутая из списка вручную, не возвращается.

`materializeAll` при заданном `cycle` правит список так:

- запись `-имя` не трогается ни добавлением, ни удалением роли;
- новая роль дописывается в конец включением; несколько новых — по алфавиту.
  Не пополняется только список из одних исключений: новая роль там листается
  и без записи. Пустой список — не исключающий: новое имя дописывается и в
  него;
- пропавшая роль, у которой в списке было включение `имя` и не было `-имя`,
  — `имя` заменяется на `-имя` на том же месте. В остальных случаях запись не
  трогается.

`cycle` отсутствует — править нечего: листаются все роли.

Файл перезаписывается только при реальном изменении `cycle`; незнакомые ключи
и порядок ключей сохраняются.

### Правка `cycle` из меню

Tab правит `cycle`, сохраняя режим списка:

- список без ключа (листаются все) — выключение даёт `["-имя"]`, то есть
  список исключений;
- `[]` — включение даёт `["имя"]`;
- список с включениями — выключение убирает имя, включение дописывает в
  конец;
- список из одних исключений — включение убирает `-имя`, выключение
  дописывает; уход последнего исключения удаляет ключ, и снова листаются все
  роли.

Битый манифест не правится: Tab ничего не меняет и выводит предупреждение.

### Отсутствующий и битый манифест

Отсутствующий манифест равен пустому: `materializeAll` создаёт пустой файл
(`{}`) и дальше применяет дефолты: листаются все роли, роль старта не задана.

Битый манифест — не разбирается JSON, `default` или `cycle` не того типа —
`materialize` не перегенерирует: показывает предупреждение и применяет те же
дефолты. Файл с ошибкой остаётся на диске для починки руками.

Предупреждения — о битом манифесте и о неработающих исключениях — CLI печатает
в stderr и завершается успешно, расширение показывает уведомление один раз на
уникальный текст за сессию.

### Конфигурация в репозитории

В репозиторий кладётся `roles.json` с `default: preflight` и
`cycle: [design, preflight, develop]` — пример из постановки. Остальные роли
каталога остаются доступны через `/role`, но в цикл не входят; их
материализованные файлы на месте, поэтому обновление их не дописывает.

## 4.3. Фолбэки

- Отсутствующий `cycle` → все роли: установка без манифеста сохраняет
  прежнее поведение.
- Отсутствующий `default` → роли нет: жёсткий `develop` больше не
  подставляется.
- Запрошенная роль не грузится → уведомление и попытка `default`: сессия,
  возобновлённая с удалённой ролью, не остаётся без роли.
- Смешанный список → предупреждение о неработающих исключениях; список не
  нормализуется: это рукописная правка, автор сам уберёт лишнее.
- Имя без файла → пропуск: файл могли удалить в открытой сессии.
- Битый манифест → предупреждение и дефолты: сессия работает, файл с ошибкой
  не затирается.
- Отсутствующий манифест → пустой файл и дефолты: первый запуск на чистой
  машине не начинается с ошибки.

## 4.4. План реализации

`materialize.ts`:

- `type Manifest = { default?: string; cycle?: string[] }` — записи `cycle`
  хранятся как есть, со знаком.
- `roleNames(agentDir): string[]` — имена `roles/*.md` по алфавиту (переезд
  `listRoleNames` из `index.ts`; используется и обновлением, и режимами).
- `loadManifest(agentDir)` — читает и проверяет типы; возвращает
  `{ manifest, raw, missing, problem }`; `raw` хранит незнакомые ключи.
- `resolveCycle(agentDir, manifest): { names: string[]; warnings: string[] }` —
  применяет режимы и отсев имён без файлов.
- `saveManifest(agentDir, raw, manifest)` — запись с сохранением незнакомых
  ключей, только при изменении `cycle`.
- `updateCycle(agentDir)` — правила обновления; возвращает
  `{ manifest, problem }`; `cycle` отсутствует — не пишет.
- `setCycleMembership(agentDir, name, inCycle)` — правка `cycle` из меню с
  сохранением режима списка.
- `materializeAll(agentDir, warn): Manifest` — `updateCycle`, раскрытие всех
  ролей, возврат действующих значений.
- Шапка модуля: добавить обновление в список обязанностей, исправить
  `extensions/role` на `extensions/roles`.

`index.ts`:

- `DEFAULT_ROLE` уходит, `activeName: string | null`.
- `requestedRole`: запись сессии → `--role` → `default`; ничего не задано —
  роли нет.
- `session_start`: `materializeAll(getAgentDir(), warn)`; `warn` показывает
  `ctx.ui.notify(..., "warning")` один раз на текст.
- `activateRole`: читает `roles/materialized/<имя>.md`, вызова `materializeOne`
  нет; если файла нет — уведомление, что роль подхватит `/reload`.
- `cycleRole`: `loadManifest` и `resolveCycle`; предупреждения — через `warn`;
  пустой список — выход; активной роли нет среди кандидатов — старт с первой
  записи.
- `updateStatus`: без роли показывает `role:—`.
- `/role` без аргумента: меню ролей с правкой `cycle` на Tab; вне TUI —
  обычный селектор (RPC) или список в notify.
- Шапка файла: манифест вместо `DEFAULT_ROLE`.

`roles.json`: создать с `default: preflight` и
`cycle: [design, preflight, develop]`.

`extensions/roles/TESTING.md`: сценарии probe и ручного прогона.

## Проверка

`extensions/roles/probe.mjs` импортирует функции `materialize.ts` напрямую
(`node` запускает `.ts` без сборки — так же работает `make materialize`) и
прогоняет сценарии на временной агентской директории.

Режимы:

- отсутствующий `cycle` — все роли;
- `[]` — кандидатов нет;
- только исключения — все, кроме исключённых;
- есть включения — только включения, о неработающих исключениях
  предупреждение;
- имена без файлов пропускаются.

Обновление:

- новый файл роли дописывается включением в конец по алфавиту — и в список
  с включениями, и в `[]`; не дописывается только в список из одних
  исключений;
- пропавшая роль с включением заменяется на `-имя` на месте;
- записи `-имя` добавления и удаления не трогают;
- имя, вычеркнутое вручную (материализованный файл на месте), не
  возвращается;
- `cycle` без изменений — файл не перезаписывается, даже если формат другой;
- незнакомые ключи манифеста сохраняются;
- битый манифест: предупреждение, файл не тронут, действуют дефолты.

Меню:

- Tab выключает и возвращает роль в `cycle` во всех режимах списка;
- уход последнего исключения убирает ключ — снова листаются все роли;
- битый манифест правку не выполняет, файл не переписывает;
- цвета и курсор: роли из `cycle` обычные, выключенные приглушены, курсор на
  текущей роли; Enter активирует, Esc закрывает.

Сессия проверяется вручную: старт с `default`, Ctrl+R по кандидатам, `/role`
— меню по всем ролям, отсутствие роли при незаданном `default`.
