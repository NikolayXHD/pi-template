# Решения и отклонённые альтернативы

Принятые решения @NikolayXHD и причины отказов — чтобы не проходить
одни и те же круги. Хронология обсуждений и переходы позиций —
`.task/done/22_generalized-template-variables/interview.md`, здесь её
нет сознательно. Метки вида `(review-1, N4)` — находки ревью
реализуемости: `.task/done/22_generalized-template-variables/review-1.md`.

## Архитектура

**Расширение pi без правок кода pi.** Механизм живёт в пакете
`pi-template`; pi потребляет зеркала собственным обнаружением.

Отклонено:

- форк pi с переопределением каталогов источников и контекстной
  директорией на сессию: поверхность ребейза personal поверх релизных
  тегов растёт на всех точках (resource loader, команды, статусная
  строка, записи сессии); конвенция `X.template` даёт нативное
  потребление без правок;
- обёртка запуска в PATH, env-редирект с симлинками, перехват итогового
  промпта: грязные, ломают окружение вне нашего контроля;
- отдельный каталог материализации с хешами: третья копия данных;
  транскрипт уже хранит точные тексты, наблюдаемость дают сами зеркала
  рядом с источниками.

**Источники `X.template` + зеркала `X` рядом, штамп свежести.**
Правится только источник; `.template` не видит ни один механизм
обнаружения pi.

Отклонено: путь копии, кодирующий имена переменных (наблюдаемость
нужна на стабильном пути); зеркала на каждую сессию (умножение копий;
общие зеркала плюс лок дают тот же результат дешевле).

**Лок-протокол: перерисовка и чтение под локом.** Сессии живут в разных
процессах, зеркала общие — без лока чтение получало бы вариант чужой
сессии.

Отклонено: механизм «отдать из памяти без лока» (частичное покрытие
точек чтения — frontmatter скилов, discovery UI — не оправдывает второго
механизма); перехват и подмена read tool (встроенный инструмент не
переизобретается, хватает скобки перехватов).

## Переменные

**Машинные значения, сессионные переопределения, вычисляемые
(shell/env).** Сессионные переопределения живут в записи сессии и детям
не передаются.

Отклонено:

- прямой доступ шаблонов к env: второй канал мира мимо конфига, линта и
  штампа; вместо этого паттерн переменной над `{"env": "VAR"}`;
- строковая подстановка значений в текст shell-команд: инъекция
  (review-1, N4). Значения передаются окружением; имя переменной — имя
  env, алиас не вводится;
- одна зона выполнения команд: нужны обе — каталог агента и проект
  (review-1, N5), поэтому поле `cwd`;
- имена партиалов с правилом одноимённости: имя — путь от корня каталога,
  уникальность по построению (review-1, N6).

**`model`, `level` — неявные факты сессии.** Движок кладёт их в view
всегда, объявление в конфиге — ошибка.

Отклонено: объявление их переменными конфига — у факта нет степеней
свободы (имя, формат, домен задаёт pi: `provider/modelId`, уровни
`off`…`max`), объявление добавляло бы бойлерплейт с режимом отказа
(кривой список значений, статический `current` вместо факта).

**Коллизия имени переменной с окружением процесса — ошибка конфига.**
Иначе значения view и окружение процесса врут друг про друга под одним
именем.

## Роль

**Роль — динамический партиал над переменной:**
`{{> (concat "roles/" role ".md")}}`. Добавление роли — создание файла.

Отклонено:

- роль как сущность движка: задача — растворить роль в механизме
  шаблонов как частный случай переменной;
- диспетчер `{{#if (eq role "x")}}…` как основная форма: лишняя работа
  на каждую роль; форма остаётся легальной, но не рекомендуемой;
- дописывание роли в конец системного промпта: новая сущность без
  необходимости; порядок секций решает автор AGENTS.md партиалом.

## Провал рендера

**Кэш последнего успеха = содержимое зеркала; сырых тегов в промпте не
бывает.** Провал файла — зеркало не трогается; зеркала нет — ресурс
выпадает целиком, громкое предупреждение.

Отклонено:

- сырые теги при провале: мусор модели; видимость ошибки даёт
  предупреждение;
- блокировка старта или хода (throw, гейт на input-событии): pi гасит
  ошибки обработчиков `before_agent_start`/`input` (review-1, N1), гейт
  добавлял бы обходной UX без выигрыша. Старт блокировать расширение не
  может и не пытается.

## Субагенты

**Полное разворачивание шаблонов в дочерних сессиях — требование, а не
опция.** Шаблоны работают в субагенте — или задача шаблонизации
выбрасывается; третьего не дано. Цена требования — реестр обязательных
расширений: на `session_start` расширение регистрирует себя для детей
сессии (`registerRequiredChildExtensions`), дети получают его через
launch-конфиг.

Отклонено:

- полумеры (например, агентские промпты «только машинными значениями»):
  любая полусемантика означает «либо шаблоны, либо субагенты»;
- жёсткая валидация запусков (`requireForAllRunners`): файлы не битые —
  зеркала держат последний отрендеренный текст, контекст связный, валить
  запуск не нужно; политика — best effort предупреждение;
- детекция дочерней сессии собственными механизмами: свои механизмы для
  чужой области не создаются; тезис «существующие механизмы её не дают»
  опровергнут `research-child-identity.md` — тег `<active_agent name="…"/>`
  даёт идентичность ребёнка без правок pi-subagents;
- заимствование имени env-переменной `PI_SUBAGENT_CHILD` для внутренней
  переменной: одно имя — два предиката («процесс — фоновый раннер»
  против «сессия — ребёнок»), смысл зависит от контекста;
- публикация происхождения ребёнка правкой pi-subagents: создание
  механизма в чужом коде.

**View дочерней сессии:** свои `model`/`level` из параметров спавна,
кастомные переменные — дефолтные значения, вычисляемые — в зоне
ребёнка. Скрытие контента от детей — решение пользователя через дефолты
переменных (пустые, непустые, вычисляемые от состояния мира), не
механика движка.

## Промпты агентов

**`agents/*.md` шаблонизируются на общих основаниях, полная семантика
переменных.** Промпт ребёнка pi-subagents строит в процессе спавнающего
(`buildEffectiveSystemPrompt`) и передаёт готовой строкой, поэтому
чтение агентского файла целиком накрывается лок-скобкой спавна.

Отклонено: оставить агентские промпты простым markdown (полумера, см.
выше); рендер агентских промптов усечённой семантикой — то же.

## UX и записи

**`/var`** — обобщённое меню переменных; смена переменной — запись
`customType: "var"`; resume — последнее значение по записям сверх
машинных значений.

Отклонено: сохранение `/role`, `cycle` и Ctrl+R из расширения roles —
роль частный случай переменной, листание не переносится; записи
старого формата (`customType: "role"`) игнорируются.

### В1. Политика при удалении источника `X.template`

Перечень источников строится по файлам `X.template`. Удалённый источник
выпадает из перечня, зеркало `X` со штампом остаётся и потребляется pi как
обычный файл — без предупреждения. Удалил скил — его текст продолжает
попадать в контекст.

Варианты:

- (а) удалять зеркало и штамп вместе с источником, с предупреждением:
  зеркало — порождённый файл, живёт, пока жив источник; риск — источник мог
  пропасть из-за сбоя (недоступный каталог), тогда исчезнет и контекст;
- (б) оставить зеркало, но громко предупреждать при каждом пересчёте:
  контекст не пропадает молча, но призрак живёт, пока не удалишь вручную;
- (в) молчаливый призрак зафиксировать как норму.

Позиция @pi-agent — (а): правило «правится только источник» честно читается
как «нет источника — нет зеркала», предупреждение делает исчезновение
видимым.

@NikolayXHD: вопрос поставлен неверно. Удаление `X.template` — это «не
управлять файлом шаблоном», а не «удалить файл». Зеркало остаётся обычным
файлом: править и удалять его — руками пользователя, ему никто не мешает.

Решение принято, 2026-10-14: механика как есть (файл не трогается),
предупреждение не требуется. Дизайн дополнен уточнением в разделе

Статус: решено.

### В7. Машинные спавны при зарегистрированном обязательном расширении

Контекст: вызов `subagent` может запустить агента не в процессе
родителя, а на другой машине (параметр `machine`). Через провод едут
только имена и флаги: имя агента, имена скилов, модель. Файлы не
переезжают — промпт агента строится на той машине из её файлов: мост
(`herdr-pi-bridge.js`) ищет там агента и скилы по именам и собирает
системный промпт сам (нет их на той машине — ошибка «Configure them on
the saved machine»). Наше расширение живёт файлами на этом компьютере и
для того мира не существует — и это нормально: тот мир самодостаточен.

Проблема: мы регистрируем расширение обязательным для дочерних сессий
(иначе дети в нашем процессе не грузят его и получают сырые теги). При
вызове с `machine` это требование — «загрузи расширение по пути
`/home/kolia/…`» — невыполнимо на той машине, и pi-subagents отказывается
стартовать спавн целиком. Поломка не «там не будет шаблонов», а «спавн
вообще не начинается» — с ошибкой `serializeHerdrPiLaunch`
(`herdr-placed-run.js`) «Pane-native remote Pi cannot transfer local
extension paths…». Дизайнское «запуск не валится» неверно.

Решение @NikolayXHD, 2026-10-14: ничего не делать. Если автор
pi-subagents сделал опцию, чей эффект — «сломай запуск удалённого
агента», это его семантика и его проблема, а не наша. Расширение
пользуется реестром как задокументировано, ограничение не обходит и не
маскирует: никаких перехватов `subagent`, правок чужого кода и костылей
не будет.

Отклонено:

- перехват вызова `subagent` с `machine` ради ясной ошибки — лишняя
  привязка к имени инструмента и схеме аргументов pi-subagents
  (@pi-agent, вариант «А»);
- правка pi-subagents (форк или PR) — поддержка чужого кода ради
  функции, которой @NikolayXHD не пользуется (@pi-agent, вариант «Б»);
- включение `requireForAllRunners` — ломает внешние CLI-спавны, которые
  сейчас работают, ради текста ошибки (@pi-agent, мусорный вариант).

Ограничение фиксируется в design.md как поведение pi-subagents; если
когда-нибудь укусит — issue в pi-subagents.

Статус: решено.

### В8. Запись квалификатора `@`

### В9. Итоги исследования точек потребления

Решения @pi-agent, 2026-10-15, по `research-consumption.md`
(исполнитель helper-local).

1. **Доставка содержимого в промпт — не `reload`.** Прежняя посылка
   («перечитывание — единственный путь доставить содержимое в память
   pi») неверна: нативный походовой путь — `before_agent_start` мутирует
   `systemPromptOptions`, pi доставляет изменённые секции дельтой
   транскрипта того же хода (им пользуется pi-subagents). `reload` тяжёл
   (замена рантайма расширений, блокировка интерфейса), не может
   случиться в середине хода и доставляет текст лишь следующим ходом —
   при походовом пересчёте вычисляемых переменных непригоден. Решение:
   содержимое промпта доставляется через `before_agent_start`, `reload`
   из механизма доставки выведен; slash-команды промпт-шаблонов
   обновляются `/reload`.

2. **Точка снятия лока — `tool_execution_end`.** `tool_result` не
   шлётся на путях, где инструмент не выполнялся (блок, ошибка, abort),
   а `tool_execution_end` шлётся на всех финализациях. Безусловной
   гарантии нет: зависший `execute` не даёт ни одного события — владение
   ограничено таймаутом.

3. **`agents/*.md` читает не pi, а pi-subagents** — вопреки прежней
   формулировке «нативное обнаружение»: спавн (все формы) и каталог
   advertised-агентов (шапки попадают в промпт родителя списком
   доступных агентов на каждом ходу — только пока активен инструмент
   `subagent`). Уточнение В5 «агентские файлы не перерисовываются в
   пересчёте» отменяется: каталог требует отрендеренных шапок к
   `session_start`, поэтому пересчёт рендерит агентские файлы целиком
   двухэтапной перерисовкой без спавна (`model`/`level` для тела — из
   шапки или дефолт сессии), спавн перерисовывает со своими параметрами
   под локом.

Статус: решено (пункт 1 — по итогам В10).

Дополнение, 2026-10-15: механизм доставки зависит от частоты пересчёта
(В10). Походовая частота требует мутации секций в `before_agent_start`
(перечитывание не может случиться в середине хода и доставляет текст
следующим ходом); при частоте по событиям достаточно перечитывания
(`reload`) прежнего дизайна. Утверждение «`reload` из механизма доставки
выведен» действует только для походовой частоты.

### В10. Частота пересчёта view

Вопрос @pi-agent, 2026-10-15: как часто пересчитывать вычисляемые
переменные и перерисовывать шаблоны? Формулировка «каждый ход» жила в
design.md («Частота пересчёта view») без согласования.

- (а) только по событиям: старт сессии, `/var`, смена модели, правка
  исходников; мир захотелось освежить — `/reload`;
- (б) перед каждым ходом: мир всегда свежий, цена — shell-команды
  вычисляемых переменных на каждый вызов модели (до 5 с на команду).

@NikolayXHD, 2026-10-15: вариант (а) и жёстче — контекст текущей
сессии автоматом не обновляется вообще никогда: непредсказуемая смена
промпта из-за другого ответа shell-команды неприемлема.

Решение: расширение держит в памяти две версии набора файлов,
влияющих на контекст сессии, — применённую и актуальную; автоматически
меняется только актуальная, её расхождение с применённой показывается в
статусе («промпты отстали»). Применение — только явное: старт новой
сессии, `/reload`, кнопка в меню команды расширения. Вычисляемые
переменные считаются на старте и по явным командам меню (одной или
всех), не автоматически.

Требование к UX: РОВНО ОДНА команда расширения, никаких разных команд.
Меню показывает статус промптов (актуальны/устарели), возраст
рассчитанных значений shell/env-переменных, позволяет сменить сессионную
переменную (без авто-применения), пересчитать указанную переменную,
пересчитать все, применить контекст явной кнопкой.

Статус: решено.

### В11. `model@`/`level@` в шапке агентского файла

@NikolayXHD, 2026-10-15: запрет избыточен — любая переменная, включая
квалифицированные, может стоять в шапке; причина запрета — нежелание
делать второй проход для шапки.

Решение: запрет снимается. Шапка рендерится итерациями до фикс-точки:
первый проход — с предварительными `model`/`level` (параметры спавна
поверх дефолта сессии), разбор YAML, следующие — с фактическими
значениями. Единственная истинная неопределённость — `model@`/`level@`
внутри выражения самой модели или уровня: повтор состояния при
итерациях — ошибка рендера «модель шапки зависит от `model@`». В теле
`model@`/`level@` — фактические значения, как и было.

Перерисовка без спавна и спавн используют один код: разница только в
предварительных `model`/`level` (дефолт против параметров спавна).

Статус: решено; правка движка (снять линт-запрет, итерации и детект
цикла) — следующим заходом.

### В12. Владение локом

@NikolayXHD, 2026-10-15: не годится полагаться на сброс протухших локов
как на единственную страховку — инструменты легально бывают долгими,
и таймаут владения лучше, чем держать лок до посинения.

Решение: владение всегда ограничено коротким таймаутом — на время
рендера и чтения (секунды), независимо от длительности инструмента.
Запись зеркала и снятие лока — только при подтверждённом владении
(маркер владельца): утративший владение не пишет и чужой лок не снимает,
а повторяет перерисовку. Зависший `execute`, не дающий событий,
задерживает только свою попытку — лок протухает сам.

Статус: решено.

Уточнение @NikolayXHD, 2026-10-15: модель конкуренции при локе —
пессимистичная (блокировка на время чужого чтения); оптимистичная — это
отклонение коммита по изменившейся метке чтения, и к чужому чтению она
неприменима. Формулировка «оптимистичная модель» в обсуждении была
ошибкой @pi-agent.

### В19. Быстрый переключатель переменных

@NikolayXHD, 2026-10-16: строка статуса показывает одну переменную,
какую — помнит `template.json` (поле `statusVariable`); прежний вывод
переопределений уходит. `alt+r` перебирает текущую переменную (по
объявленным, у которых есть список значений) и запоминает выбор в
конфиге; `ctrl+r` перебирает значение текущей переменной и НЕ применяет
(см. В10 — применение только явно): значение становится сессионным
переопределением, контекст помечается устаревшим. Клавиши ровно
`ctrl+r`/`alt+r`;
занятость `ctrl+r` в pi (`app.session.rename`) эмпирически не мешает —
обе привязки работают.

Статус: решено.

Уточнение реализации, 2026-10-16 (отчёт помощника): при отсутствии
кандидатов `alt+r` даёт предупреждение; вычисляемая переменная со списком
попадает в кольцо `alt+r`, но `ctrl+r` не может её переключить — отказ
движка с предупреждением (вычисляемые переменные имеют только
машинное значение); строка статуса без поля `statusVariable` остаётся
глифом без переменной.

Статус: реализовано.

### В20. Статус переменной в меню

@NikolayXHD, 2026-10-16: строка статуса знает только общее состояние
(«шаблон устарел»), этих данных достаточно, чтобы показать статус по

Уточнение, 2026-10-18: `model` и `level` — строки общего списка (отдельная
строка убрана), им тоже нужен статус: они меняются в течение сессии.

Статус: решено.

### В21. Устаревание по тексту; статус на заголовке меню
