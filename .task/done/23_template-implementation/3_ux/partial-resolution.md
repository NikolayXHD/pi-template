# Правка движка — включения без предварительного обхода

Решение @NikolayXHD: предварительный обход каталогов для реестра частиалов
убирается. Имя включения ищется на диске в момент рендера. Проверка имён
по значениям переменных остаётся (раннее предупреждение вместо падения
посреди сессии).

## Что сделать

1. Реестр частиалов (обход каталогов, карта имя → путь, сборка текстов
   заранее) убрать. Имя включения — путь от корня: без префикса — от
   каталога агента, с префиксом `.pi/` — от корня проекта. Текст — из
   `X.template`, если он есть, иначе из `X`. Нет ни того, ни другого —
   ошибка: статическое имя — ошибка линта, динамическое — ошибка с
   указанием значения.
2. Проверка значений остаётся: для каждого значения переменной в
   динамическом включении `{{> (concat ...)}}` имя проверяется прямо на
   диске (есть `X.template` или `X`); нет — предупреждение с именем, как
   сейчас. Статические имена проверяются на существование так же.
3. Текст включения читается в момент рендера (кэш на проход), чтобы не
   читать файлы, которые не включены.
4. Следствия: предупреждение «частиал зарегистрирован из двух файлов»
   исчезает — имя указывает на один путь по правилу «источник
   предпочитается»; проблемы обхода каталогов исчезают.
5. `README.md`: правило включений — имя ищется на диске в момент рендера;
   текст из `X.template`, если он есть, иначе из `X`; предварительного
   обхода каталогов нет.
6. `probe.mjs`: включение из произвольного каталога
   (`modes/plan.md.template`), включение без источника (`modes/plan.md`),
   отсутствующий файл в статическом имени (ошибка линта), отсутствующий
   файл для значения динамического имени (предупреждение), имя с `.pi/` —
   от корня проекта. Существующие сценарии реестра привести к новому
   правилу.
7. Проверки: `node probe.mjs`, `node live/typecheck.mjs`, живые скрипты.
   Отчёт — раздел «Partial includes» в `3_ux/report.md`. Коммиты не
   делать.
