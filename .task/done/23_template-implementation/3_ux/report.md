## Esc и язык

### Esc — шаг назад

- Меню собрано в цикл (`runMenuUntilExit` в `ui.ts`): команда не
  завершается после первого действия, а возвращается к выбору пункта,
  пока не закрыт корень меню.
- Смена переменной возвращает исход `cancelled`, когда диалог значения
  отменён: и список значений (`ctx.ui.select`), и ввод строки
  (`ctx.ui.input`) при Esc/отмене отдают `undefined`. В этом случае цикл
  переоткрывает меню — интерфейс не закрывается.
- Полное закрытие — только Esc в корне меню: `done(undefined)` корневого
  компонента завершает команду.
- Курсор возвращается на ту же строку: индекс выбранного пункта
  передаётся в следующее открытие TUI-меню (в RPC-режиме курсора нет).
- Других диалогов у меню нет: все точки отмены — эти два, оба следуют
  правилу «Esc — назад».

## Перерисовка файлов (2026-10-16)

Последний пункт меню переделан: вместо «apply all and reload» — кнопка
`rewrite files on disk`, которая только перерисовывает целевые файлы на
диске по текущим значениям переменных сессии. Требование @NikolayXHD:
ничего не применять к текущей сессии, ничего не перечитывать, сессию не
трогать. Термин: по уточнению @NikolayXHD «зеркало/mirror» отменён —
целевой файл (`target`), уведомление кнопки — `pi-template: targets
rewritten`.

### Поведение

- `TemplateSession.rewriteFiles()` пишет актуальную версию в целевые файлы
  тем же механизмом, что применение (`writeVersion`): каждый источник
  целиком, только при расхождении текста, запись атомарная (временный файл
  плюс переименование); целевые файлы, совпавшие с актуальной версией, не
  трогаются.
- Применения нет: применённая версия и `appliedView`, `pendingDelivery` и
  доставка секций не меняются; записи сессии (`"var"`) не создаются;
  статусная строка не пересчитывается.
- Перечитывания нет: рантайм расширения и загрузчик pi не перезапускаются,
  сессия продолжает работать как есть.
- Семантика версий: перерисовка не выравнивает версии; если целевые файлы
  ушли впереди памяти сессии — это штатное «prompts are stale», выравнивают
  кнопка применения (`update current session context`) или `/reload` самой
  pi.
- Единственный пользовательский отклик — одно info-сообщение
  `pi-template: targets rewritten` (подтверждено supervisor'ом: вариант
  «одно info-уведомление»); предупреждение `pi-template: nothing to
  rewrite`, если перерисовывать нечего.
- Кнопка `update current session context` (apply) осталась отдельной и без
  изменений.

### Файлы

- `session.ts` — публичный `rewriteFiles()`: запись актуальной версии в
  целевые файлы без применения.
- `ui-model.ts` — действие `rewriteFiles` вместо `applyAll`, подпись

### Развилки, согласованные с ведущим

В спеке не были описаны два следствия отказа от обхода каталогов; решение
по ним получено через supervisor-канал:

- сверка устаревания: штампуются файлы включений последнего рендера вместе
  с парным кандидатом (`X.template` и `X`) — правка, появление и удаление
  любого из пары помечают контекст устаревшим; включение, не попавшее в
  последний рендер, на устаревание не влияет. Поведение «правка `roles/**`
  перерисовывает актуальную версию» сохраняется без обхода каталогов;
- текст включения линтуется в момент чтения, без `agentName` (`@` во
  включении остаётся ошибкой): нарушение словаря падает у включателя как
  `partial "x": …`; тихая пустота вместо ошибки переменной недопустима.

### Что сделано

- `sources.ts`: `discoverPartials`, `readPartials` и `PartialRegistry`
  удалены; добавлен `createPartialResolver` — имя включения есть путь от
  корня (без префикса — от каталога агента, с `.pi/` — от корня проекта),
  текст берётся из `X.template`, иначе из `X`. Существование и текст
  проверяются в момент вызова; имя, выходящее за корень (`..`, абсолютное)
  или указывающее на каталог, не разрешается; нечитаемый файл — исключение
  с именем включения и путём. Предупреждение «частиал зарегистрирован из
  двух файлов» и проблемы обхода каталогов исчезли вместе с реестром.
- Резолвер живёт один проход рендера и кэширует чтения, вложенные
  включения обслуживаются тем же кэшем. `renderCurrent` создаёт резолвер на
  проход, `renderForApplied` (чужое чтение) — свой; его чтения в отпечатки
  не попадают.
- `render.ts`: замыкание включений собирается в момент рендера, файлы, не
  попавшие во включения, не читаются; текст включения проходит тот же
  линт, что источник. Линт имён на диске: статическое имя при отсутствии —
  ошибка, динамическое — предупреждение по каждому значению из списка,
  отсутствующее выбранное значение — ошибка рендера с указанием имени.
  Предупреждения текстов включений собираются в `warnings` контекста.
- `render-set.ts`: `preparePartials` убран; `renderSources` линтует каждый

- `agent.ts` и `session.ts` переведены с карты текстов на резолвер;

## Quick switch (2026-10-16)

Задание — `3_ux/quick-switch.md` (с уточнением ведущего по ходу захода:
`ctrl+r` ничего не применяет). Baseline — `061d527` («status line: one
state glyph, no words»): рабочая копия на входе чистая. Правки не
закоммичены, ничего не застейджено.

### Поведение

- Строка статуса — `template <глиф>` плюс пара переменной, названной
  полем `statusVariable` верхнего уровня: `template ✓ role=develop`.
  Значение берётся из вида сессии и сжимается как прежние
  переопределения (лимит 16 символов, `…`); пустое значение — `—`. Без
  поля строка — только глиф, как раньше. Прежний вывод переопределений
  (`role=develop`, `+N`) ушёл; факт переопределения остался в меню
  (`session override`).
- `ctrl+r` (в pi занято «переименовать сессию») — следующее значение
  текущей переменной по кольцу её списка значений. Значение становится
  сессионным переопределением: пишется запись `"var"`, текущая версия
  перерисовывается, контекст НЕ применяется — только помечается
  устаревшим (глиф `!`). Уведомление говорит о новом значении:
  `pi-template: role = develop`. Нет текущей переменной или списка —
  вызов ничего не делает.
- `alt+r` — следующая переменная кольца: объявленные, у которых в
  текущем виде непустой список значений, в порядке объявления. Выбор
  сразу пишется в `template.json` (разбор JSON, правка поля, атомарная
  запись: временный файл плюс переименование), файл перечитывается и
  валидируется заново, статус перерисовывается. Уведомление
  `pi-template: status variable = mode`.
- Обе клавиши работают только в интерактивном режиме: вне него
  (RPC/headless) вызов ничего не делает (проверка `ctx.mode !== "tui"`).
- pi не даёт перебить `ctrl+r` молча: при регистрации он сообщает
  конфликт с `app.session.rename` и оставляет клавишу расширению — это
  осознанно; переименование сессии по `ctrl+r` в такой сессии
  недоступно.

### Развилки

- Семантика `ctrl+r` — по уточнению ведущего: без применения. В файле
  задания пункт 3 «Поведения» поправлен, но пункты 4 и 5 «Что сделать»
  всё ещё говорят «с применением»; выполнен вариант без применения.
- Проверка `statusVariable` в конфиге: поле должно называть объявленную
  переменную, у которой объявлен непустой список значений; список-команда
  `{"shell": …}` принимается — пустоту можно узнать только в рантайме.
- Кандидаты `alt+r` — по текущему виду (`currentValues()`): переменная с
  провалившейся командой списка в кольцо не попадает. Вычисляемая
  переменная со списком в кольцо попадает (в задании — «с непустым
  списком значений»); `ctrl+r` на ней получает отказ движка («computed —
  override not allowed») и предупреждение.
- `alt+r` без кандидатов — предупреждение `pi-template: no variable with
  a values list` (в задании случай не описан).
- Запись файла нормализует форматирование: значения остальных полей
  сохраняются, исходная раскладка файла — нет.

### Ручной сценарий

1. `template.json` с `statusVariable` на переменную со списком (например
   `role`, значения `preflight`, `develop`). Запустить pi: строка
   `template ✓ role=preflight`.
2. `ctrl+r`: значение меняется на следующее, статус
   `template ! role=develop`, в сессии запись `"var"`, промпт и целевые
   файлы не меняются; уведомление `pi-template: role = develop`.
3. `alt+r`: строка статуса показывает следующую переменную кольца
   (`mode=plan`), `statusVariable` в `template.json` обновлён,
   уведомление `pi-template: status variable = mode`.
4. `ctrl+r` ничего не делает, когда поля `statusVariable` нет либо когда
   список текущей переменной не вычислился (команда списка упала).
5. При старте pi печатает предупреждение о конфликте `ctrl+r` с
   «rename session» — ожидаемо.

### Остаточные риски

- `ctrl+r` перехватывает встроенную pi «переименовать сессию»: в сессии
  с расширением она по этой клавише недоступна (осознанный выбор
  задания).
- `alt+r` перезаписывает `template.json` целиком с форматированием по
  умолчанию: значения сохраняются, исходная раскладка файла — нет.
- Живой прогон вызывает обработчики клавиш напрямую (реальная
  регистрация и конфликт — через `getShortcuts`); нажатие в настоящем
  терминале — за ручным сценарием.
- Вычисляемая переменная со списком может попасть в кольцо `alt+r`, но
  переключить её значение `ctrl+r` не может (отказ движка,
  предупреждение).
