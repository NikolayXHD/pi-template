# Быстрый переключатель переменных и переменная в строке статуса

Решение @NikolayXHD.

## Поведение

1. Строка статуса показывает одну переменную — какую, помнит конфиг
   `template.json` (новое поле верхнего уровня `statusVariable`): строка
   вида `template ✓ role=develop`. Прежний вывод переопределений
   (`role=develop`, `+N`) уходит — факт переопределения остаётся в меню.
2. `alt+r` — перебор переменной по кольцу: среди объявленных переменных, у
   которых есть непустой список значений. Выбор запоминается в
   `template.json` (поле перезаписывается сразу).
3. `ctrl+r` — перебор значения текущей переменной по её списку значений,
   по кольцу. Значение становится сессионным переопределением; контекст
   НЕ применяется — только помечается устаревшим (глиф `!`). Применение
   остаётся явным: кнопка меню, старт сессии, `/reload` (В10). У
   переменной без списка значений вызов ничего не делает.
4. Клавиши ровно `ctrl+r` и `alt+r`. `ctrl+r` в pi числится за
   `app.session.rename`; эмпирически клавиши не мешают друг другу
   (диалог списка сессий обрабатывает ввод сам), оба работают.

## Что сделать

1. `vars.ts`: чтение поля `statusVariable` верхнего уровня. Конфиг: поле
   должно называть объявленную переменную с непустым списком значений —
   иначе ошибка конфига (как прочих ошибок), с указанием имени.
2. Запись `template.json`: JSON → правка поля → атомарная запись.
   Ошибка записи — уведомление, текущая переменная не меняется. После
   записи конфиг перечитывается и валидируется заново, статус
   перерисовывается.
3. `ui-model.ts` / `ui.ts`: `statusLineText` — `template <глиф>
   <имя>=<значение>`, значение из вида сессии. Поля в конфиге нет — строка
   без переменной, как сейчас.
4. `index.ts`: `registerShortcut("ctrl+r", …)` — перебор значения текущей
   переменной без применения (контекст помечается устаревшим);
   `registerShortcut("alt+r", …)` — перебор переменной с записью в
   `template.json`. Без UI (headless/RPC) вызов
   ничего не делает.
5. `probe.mjs`: статус с переменной и без; перебор значения (кольцо,
   применение, отсутствие списка); перебор переменной с проверкой записи
   в `template.json` (поле обновилось, остальное содержимое не тронуто);
   ошибка конфига (необъявленная переменная, переменная без списка).
6. `README.md`: строка статуса с переменной, поле `statusVariable`,
   горячие клавиши. `TESTING.md` — ручные сценарии.
7. Проверки: `node probe.mjs`, `node live/typecheck.mjs`, живые скрипты.
   Отчёт — раздел «Quick switch» в `3_ux/report.md`. Коммиты не делать.
