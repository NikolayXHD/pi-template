## Находки

### C1 (minor) — фикстура «игнора `role`» не различает проверки `type`/`customType`

`probe.mjs:2185-2191` (сценарий
`when_var_entries_read_then_last_value_per_name`): старая запись дана как
`customType: "role"` с payload `{name, model, level, text}` — без `value`;
запись `type: "message"` не имеет ни `customType`, ни `data`. Читатель
(`ui-model.ts:31-42`) фильтрует и по `type === "custom"`, и по
`customType === "var"`, и по строковым `name`/`value`; обе «чужие» фикстуры
отсеиваются уже проверкой `value` — значит сценарий пройдёт и после снятия
гейтов `type`/`customType`. Живой resume-прогон (`report.md:152-154`)
использует такую же неразличающую запись `role`. Дискриминирующая фикстура —
чужой `customType` (и `type: "message"`) с валидным `{name, value}`: тогда
«игнор `"role"`» (инвариант спеки, чек-лист п.1–2) действительно закреплён
test'ом. Код корректен; замечание к силе доказательства, заявленного в
`report.md:104-105`.

### C2 (minor) — ветки UI без прогонов и без записи в остаточные риски

- `ui.ts:293` — ввод строки для переменной без списка `values` (единственный
  путь смены для легального конфига без `values`). В live-скрипте конфиг
  даёт всем переменным список или вычисление, `ctx.ui.input` не вызывается
  ни разу; ручные сценарии (`report.md:161-164`) тоже предполагают
  переменную со списком значений.
- `ui.ts:306-311` — дайджест при `!ctx.hasUI`; сценария с `hasUI = false`
  нет ни в probe (ui.ts вне probe), ни в live-скрипте (UI-заглушка всегда
  есть). Ветка заявлена в `report.md` (C.1).
- `ui.ts:85-88` — «сессия не найдена»; тоже без прогона, хотя заявлена.

В `report.md:217-230` (остаточные риски) ни одна из этих веток не названа —
там только TUI-заглушка, RPC-диалоги, классификация computed, ширина
статуса и таймаут shell. Достаточно либо добавить прогон, либо перечислить
в остаточных рисках.

### C3 (nit) — сценарий про неявные проверяет недостижимое в бою состояние

`probe.mjs:2239` подсовывает `model`/`level` в `currentValues()`. В живой
сессии `currentValues()` содержит только объявленные переменные
(`vars.ts:201-289`), а объявление `model`/`level` — ошибка конфига
(`vars.ts:449-450`), view не строится. Поэтому флаг `implicit` и пропуск в
`menuItems` (`ui-model.ts:108-116`) — защита на будущее; фактическую
гарантию «неявные не предлагаются» даёт отсутствие их в facts, а
read-only-показ — строка шапки (`ui.ts:185`). Отчёт (`report.md:109-111`)
подаёт сценарий как проверку инварианта; дешевле закрепить реальное
поведение утверждением в `when_menu_facts_from_session_then_age_and_override`
(что facts живой сессии не содержат `model`/`level`).

### C4 (nit) — вне TUI неявные `model`/`level` не показываются вовсе

Спека (ловушка): «вычисляемые и неявные переменные … read-only — но
показываются». TUI показывает их строкой шапки (`ui.ts:185`); RPC-ветка
(`ui.ts:113-122`, заголовок `ui.ts:301-303`) и дайджест (`ui.ts:306-311`) их
не выводят.
Режим RPC в спеке не описан, решение задокументировано (`report.md:211-213`),
но это ограничение не названо ни в «Поведении» как режимное, ни в
остаточных рисках.

### C5 (nit) — построение пунктов меню вне try/catch команды

`ui.ts:96-99`: `menuItems(variableFacts(session, overrides))` вычисляется до
`try`, а catch обещает «сбой UI/сессии не должен ронять команду». Геттеры
`TemplateSession` простые, и ветка маловероятна, но fail-safe неполон —
перенос вычисления в `try` (или сужение комментария) убрал бы расхождение.

## Сверено и совпало

- **Ровно одна команда.** `ui.ts:44-50` — единственный `pi.registerCommand`
  (`/template`); `registerShortcut`/`registerTool` в пакете нет; механика
  `cycle`/Ctrl+R не перенесена.
- **Запись `"var"`, payload строго `{name, value}`.** `ui-model.ts:15-23`;
  единственный `pi.appendEntry` — `ui.ts:273`; других записей
  расширение не пишет (git grep по `appendEntry`). Строгость payload
  проверена `probe.mjs:2208-2232`.
- **Игнор `"role"` и чужих записей.** `ui-model.ts:35` (гейты
  `type === "custom"` и `customType === "var"`), битые payload
  отбрасываются (`ui-model.ts:36-40`); последнее значение — по порядку
  следования записей. Замечание к фикстуре — C1.
- **Статусная строка одним ключом.** `ui.ts:32,54-72,75-80`; текст —
  `ui-model.ts:143-156`, компактность — `ui-model.ts:190-203`: `template ·
  промпты актуальны/отстали`, до трёх пар `имя=значение` (обрезка 16),
  дальше `+N`, при `!ready()` — `template · view не построен`. `setStatus`
  обёрнут в try/catch.
- **Смена переменной не применяет контекст.** `ui-model.ts:177-188` —
  только `setVariable` + запись; `session.apply()` вызывается лишь из
  `ui.ts:215` (и стартовым применением зоны B, как требует дизайн). В
  probe-сценарии зоны B зеркало после `setVariable` не меняется, `isStale()`
  становится true.
- **Вычисляемые/неявные не предлагаются к смене.** `ui-model.ts:108-116`;
  признак computed — `computedAge` (`session.ts:957-960`) совпадает с
  запретом в `setVariable` (`session.ts:980-981`) и `isComputedVariable`
  (`vars.ts:88-91`) — один и тот же предикат с тем же `agentName`, так что
  расхождение возможно лишь при изменении зоны B (названо в отчёте).
  Пересчёт — `ui.ts:207-259` (`recompute`/`recomputeAll`), возраст
  обновляется.
- **Resume сверх `initial`.** `index.ts:141-148` — ленивое чтение записей с
  кэшем по sessionId; `index.ts:181-185` — передача `overrides` в
  `session.start`; новая сессия записей не имеет; старый формат не читается;
  `reload` удаляет карту на shutdown (`index.ts:209`) и поднимает её заново.
  Живой прогон подтверждает «Роль develop» из `var`-записей при игноре
  `role` (`report.md:152-154`).
- **Порядок переменных** — объявления (`vars.ts:201-289` →
  `ui-model.ts:74-91`).
- **Обновления статуса**: `index.ts:185` (старт), `:224` (`before_agent_start`
  после сверки), `:234`/`:249` (модель/уровень, имя сессии), действия меню
  `ui.ts:216,225,251,282`; снятие — `index.ts:212`.
- **Меню**: статус, значения (вычисляемые с возрастом), смена, пересчёт
  указанной/всех, кнопка «обновить контекст текущей сессии» — порядок и
  подписи совпадают со спекой/дизайном; TUI на pi-tui `ui.ts:126-204`, RPC
  — `select`/`input`, дайджест — при отсутствии UI; ошибки (нет сессии, нет
  view, catch-all) — `ui.ts:85-100`, битый `template.json` проверен живьём.
- **Качество кода**: `ui-model.ts` без импортов pi (поэтому проверяем в
  probe), `ui.ts` — только UI/команда/статус, `index.ts` — жизненный цикл;
  erasable TS, нет `any`/`enum`, импорты с `.ts`; новых публичных имён вне
  согласованных (`/template`, `"var"`, `template.json`, `model`/`level`,
  `@`) нет — экспорты ui-модулей внутренние.
- **Тесты**: 6 новых сценариев (`dbaae79`), имена `when_..._then_...`,
  данные явные; всего сценариев 82 (`git grep -c "^scenario("`), совпадает
  с `report.md:102`; live-скрипт содержит 36 проверок — совпадает с
  `report.md` (п.3). Дублирования, кроме пересечения синтетического и
  живого сценариев меню (разные данные), не увидел.
- **Расхождений между отчётом и кодом не нашёл**: `readVarOverrides`
