# Спека — исследование точек потребления и жизненного цикла

Исполнитель: helper-local. Только чтение кода и отчёт; вход для спеки зоны
B (лок-протокол и точки потребления).

## Цель

Закрыть три вопроса, без которых спека зоны B не пишется.

1. **Перечитывание ресурсов через `reload`.** Что именно pi перечитывает
   при `reload`/`ctx.reload()`: цепочка контекстных файлов, `SYSTEM.md`,
   `APPEND_SYSTEM.md`, промпт-шаблоны, скилы (описания и тела),
   `agents/*.md`, — по каждому виду ресурса отдельный вывод. Какие события
   шлёт pi (`session_start` с причиной `reload` и др.), что происходит с
   загруженными расширениями (их рантайм заменяется?), какова цена
   перезагрузки. Есть ли иной путь доставить содержимое файлов в память pi
   без `reload`.
2. **Снятие лока при прерывании хода.** При abort шлётся ли обработчикам
   расширений `tool_result` или `tool_execution_end` для выполняющегося
   инструмента; если нет — как pi завершает `execute` (сигнал? таймаут?)
   и существует ли точка, где расширение гарантированно снимет лок.
   Требуется однозначный вывод: «точка снятия есть (какое событие)» или
   «гарантии нет, только таймаут».
3. **Точки чтения агентских файлов при спавне.** Как инструмент
   `subagent` и его формы (одиночный агент, workflow-шаги, fanout,
   вложенные вызовы) читают `agents/*.md` и где проходит построение
   промпта (`buildEffectiveSystemPrompt`). Полный перечень форм спавна,
   чтобы скобка лока и рендера в зоне B покрыла все чтения агентских
   файлов.

## Правила

- Только чтение: код не править, кроме отчёта файлы не создавать.
- Поиск: `git grep -in` по git-репозиториям; по каталогам вне git
  (pi-subagents в `npm/node_modules`, дистрибутив pi) — точечный `grep -rn`
  по `src/`, `docs/`, `dist/`; `find` и `rg` запрещены. Чтение — read с
  диапазонами, `git show` — `--stat`/`--name-only`. toolTimeoutMs 120 с.
- Новые термины не вводить; нужен новый — ask через supervisor.
- Сомневаешься в толковании — ask, лучше 3 уточнения, чем ошибка.

## Критерии приёмки

- По перечню ресурсов design.md (контекстные файлы, `SYSTEM.md`,
  `APPEND_SYSTEM.md`, промпты, скилы, `agents/*.md`) — вывод по каждому.
- По abort — однозначный ответ с указанием события или отсутствия
  гарантии.
- Перечень форм спавна `subagent` полон; для каждой — где читается
  агентский файл.
