- Реестр обязательных расширений существует: `registerRequiredChildExtensions`
  (pi-subagents, модуль `shared/required-child-extensions`) регистрируется на
  `sessionId`, поле `requireForAllRunners` необязательно. Дизайн («Субагенты»)
  укладывается: расширение регистрирует себя на сессии, запуски без поддержки
  расширений не валятся.
- Скобка лока на чтении инструмента реализуема: обработчики `tool_call` и
  `tool_result` окружают исполнение инструмента, вложенные вызовы
  `executeTool` проходят те же обработчики (docs/extensions.md). Встроенный
  read не переизобретается — соответствует дизайн-разделу «Лок-протокол».
- Записи сессии с `customType` — существующий механизм (`CustomEntry`,
  session-manager); запись `"var"` и игнор записей `"role"` ложатся на него.
- `/var` и статусная строка реализуемы: `pi.registerCommand` и `setStatus`
  есть в API расширений.

## Находки

### N1 (снята) — поведение при удалении источника

Первоначальная формулировка: перечень источников строится по файлам
`X.template`; при удалении источника зеркало остаётся и потребляется pi
без предупреждения — сочтено дырой, требующей политики удаления зеркал.

Снятие (@NikolayXHD, 2026-10-14): это норма конвенции, а не дыра. Наличие
`X.template` означает «файл управляется шаблоном»; удаление `.template` —
отказ от шаблонного управления, а не просьба удалить файл. `X` остаётся
обычным файлом, его правка и удаление — руками пользователя. Дизайн
дополнен уточнением в разделе «Конвенция `X.template`», предупреждение не
требуется.

## Предметы сверки (закрыть до спек зон)

- Перечитывание ресурсов через `reload`: docs подтверждают `/reload` после
  правки скила в активной сессии; что reload делает с цепочкой контекстных
  файлов и промптами, с кодом загрузчика ресурсов не сверено. На перечитывании
  держится доставка содержимого (design, «Лок-протокол»: «перечитывание —
  единственный путь доставить содержимое в память pi»).
- Снятие лока при прерывании хода: design («Свойства лока») сам помечает
  «гарантия точки снятия при abort — сверить по коду pi»; не сверено. Без
  гарантии лок держится до истечения таймаута — допустимая деградация, но она
  должна быть зафиксирована в спеке, а не случайна.
