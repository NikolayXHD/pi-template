# Спека — исследование механизмов идентификации дочерней сессии

Исполнитель: helper-cloud-fast, 2026-10-14. Только чтение кода и отчёт.

## Цель

Дочерняя сессия субагента должна узнавать имя агента, которым запущена,
чтобы выбирать значения переменных `@` / `@<имя>` из `template.json`
(«значение субагента», см. design.md, разделы «Субагенты» и «Агентский
файл: два этапа»). Задача — перечислить способы узнать это имя, проверив
каждый по коду, и рекомендовать механизм.

- `runs/shared/child-launch.js` кладёт `agent: childAgentName` в конфиг
  запуска ребёнка; в одном из режимов системный промпт ребёнка

  в фоновых детях.

## Что выяснить

1. Полный перечень каналов, по которым дочерняя сессия — а именно
   расширение в ней — может узнать имя агента: окружение, имя и путь
   файла сессии, записи сессии (`customType`), метаданные сессии
   (`session_info`), системный промпт, supervisor-канал, прочее.
2. По каждому каналу: каким классам детей он доступен (foreground-дети в
   процессе родителя, фоновые дети-процессы, панели Herdr и демонные
   спавны, machine-размещения); через какой API pi его видит расширение
   (`process.env`, `sessionManager`, события `session_start`,
   `before_agent_start` и т.п.); стабильность — публичный контракт или
   внутренность чужого кода.
3. Что требуется, чтобы канал был полным: какие классы детей покрыты без
   правок pi-subagents, какие — с публикацией имени агента (по образцу
   `PI_SUBAGENT_PARENT_SESSION`) и где именно это делается в коде.
4. Рекомендация: один основной механизм и запасной; для каждого —
   покрытие классов детей, цена (правки в чужом коде или нет).

## Правила

- Только чтение: код не править, кроме отчёта файлы не создавать.
- Поиск: `git grep -in` по git-репозиториям; по каталогам вне git
  (pi-subagents в `npm/node_modules`, дистрибутив pi) — точечный `grep -rn`
  по `src/` и `docs/`; `find` и `rg` запрещены. Чтение — read с
  диапазонами, `git show` — `--stat`/`--name-only`. Долгих команд не
  должно быть, toolTimeoutMs 120 с.
- Ссылки на код — файл + имя символа, без номеров строк и хешей.
- Новые термины и имена не вводить; нужен новый — ask через supervisor.
- Сомневаешься в толковании — ask, лучше 3 уточнения, чем ошибка.
