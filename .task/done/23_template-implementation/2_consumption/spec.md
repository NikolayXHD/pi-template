# Спека B — версии контекста, лок-протокол и точки потребления

Исполнитель: helper-cloud-fast. Зона B чек-листа issue.md. Рабочая копия —
`/home/kolia/git/pi-template`.

## Результат

Точка входа расширения (файл, на который ссылается `package.json`) —
жизненный цикл версий контекста сессии и все точки потребления из
design.md; тесты в `probe.mjs` (всё, что проверяемо без запуска pi) и
`report.md` с живыми сценариями для ручного прогона.

## Поведение

Источник истины — design.md задачи 23, читать целиком. Разделы зоны:
«Переменные и view», «Лок-протокол», «Версии контекста сессии»,
«Субагенты», «Агентский файл», «Провал рендера». Факты о pi и
pi-subagents уже проверены в `research-consumption.md` и
`research-child-identity.md` — не переоткрывать, опираться.

Стадии, отчёт по каждой.

**B.1. Версии и сверка.** В памяти две версии набора файлов: применённая
и актуальная. Актуальная перерисовывается при сверке mtime+size
источников на каждом `before_agent_start` (без пересчёта вычисляемых) и
по явным действиям (команды меню — зона C даст вызовы). Расхождение
версий — признак «промпты отстали». После `/reload` рантайм расширения
заменён и память потеряна: новый экземпляр принимает зеркала за
применённую версию и рендерит актуальную заново.

**B.2. Лок.** Межпроцессный, повторно-входимый (счётчик глубины по
пути), маркер владельца с временем; владение ограничено коротким
таймаутом (секунды, независимо от длительности инструмента); запись
зеркала и снятие лока — только при подтверждённом владении; утративший
владение не пишет и чужой лок не снимает. Форма лока (mkdir или
библиотечная) и имя — деталь реализации.

**B.3. Доставка в промпт.** Секции системного промпта (контекстные
файлы, описания скилов, SYSTEM/APPEND) обновляются точечной заменой в
`before_agent_start` текстом применённой версии. Применение — только
явное: старт сессии (первый `before_agent_start`: pi читал зеркала до
`session_start`), сверка фактической модели перед первым ходом, кнопка
применения (API для зоны C), `/reload` (через перечитывание зеркал:
`session_shutdown` с причиной `reload` пишет актуальную версию до
перечитывания pi). Форс `systemPrompt` не использовать. Производный
текст — развёрнутый промпт-шаблон с аргументами пользователя — не
переписывается никогда: проверить по коду pi, что именно лежит в секциях
к моменту обновления, вывод зафиксировать в отчёте.

**B.4. Чужие чтения.** `tool_call` — лок, рендер источника под view
применённой версии, запись при расхождении текста; `tool_execution_end` —
снятие с проверкой владельца. Цель — read tool (тела скилов); вложенные
`executeTool` идут теми же перехватами. Встроенный инструмент не
переизобретать и не подменять.

**B.5. Спавн.** Скобка на инструменте `subagent`: `tool_call` — лок и
двухэтапный рендер агентского файла (шапка — итерациями до
фикст-точки; предварительные `model`/`level` — параметры спавна поверх
дефолта сессии; извлечение модели и уровня из YAML шапки — в зоне B,
движок даёт шов; тело — с фактическими), запись при расхождении;
`tool_execution_end` — снятие. Перерисовка без спавна — тот же код с
дефолтом вместо параметров. Известное ограничение (design, m1): порядок
обработчиков `session_start` с pi-subagents не гарантирован, каталог
advertised может держать прошлое зеркало до следующего обновления.

**B.6. Идентичность субагента.** Признак — тег
`<active_agent name="…"/>` (`ctx.getSystemPrompt()` на `session_start`;
запасной — имя сессии). Ни тега, ни имени — сессия не субагент,
`@`-ключи не применяются; имя неизвестно — `@` применяется, `@<имя>` нет;
исчезновение тега — громкое предупреждение (конвенция pi-subagents, не
опубликованный контракт). Значения `@`/`@<имя>` — из конфига через
движок (цепочка `@<имя>` → `@` → `initial`).

**B.7. Регистрация и провалы.** `registerRequiredChildExtensions` на
`sessionId` без `requireForAllRunners`; machine и внешние CLI — как в
design (В7): не обходить, не маскировать. Провал рендера — по разделу
«Провал рендера»: зеркало не переписывается (кэш последнего успеха),
громкое предупреждение; битый `template.json` — view не строится,
перерисовки нет.

## Ловушки

- Порядок обработчиков: path-расширения грузятся раньше inline-хуков
  pi-subagents — наша замена секций успевает до форса промпта ребёнка; на
  это опираться и проверить вживую.
- `tool_result` не приходит на «immediate»-путях (блок, ошибка валидации,
  abort до `execute`) — снятие только на `tool_execution_end`.
- `session_start(reload)` приходит новому рантайму и не приходит вовсе
  без host-биндингов (print/json-режимы) — учитывать.
- Зеркала общие для сессий и процессов, «переключение зеркал» штатно;
  чужое чтение под локом получает вариант применённой версии своей
  сессии.
- Агентские файлы рендерятся и без спавна (каталог advertised); YAML-
  валидация отрендеренной шапки — сбой = провал рендера файла.
- Стиль пакета: erasable TS, без `any`, импорты с `.ts`. Публичные имена
  уже согласованы: `template.json`, `/template`, запись `"var"`, `@` /
  `@<имя>`, `model`/`level`; прочие имена — детали реализации.
- Коммиты не делать; `find`/`rg` запрещены; поиск — `git grep` по
  git-репозиториям, точечный `grep -rn` вне их (без `*.map`); чтение —
  read с диапазонами; toolTimeoutMs 120 с.
- Сомневаешься в толковании или нашёл противоречие в дизайне — ask через
  supervisor, лучше 3 уточнения, чем ошибка.

## Критерии приёмки

- `node probe.mjs` — все сценарии зелёные: движок плюс новое, что
  проверяемо без pi (версии и сверка исходников; лок: повторный вход,
  короткое владение, чужое владение не снимаем; двухэтапный рендер со
  швом извлечения модели/уровня).
- `report.md` (рядом со спекой): файлы, поведение по стадиям, команды
  проверки и результаты; живые сценарии ручного прогона (шаг и ожидание:
  старт сессии, `/reload`, кнопка применения, read тела скила, спавн,
  каталог advertised); вывод по проверке производного текста
  промпт-шаблонов; вопросы и возражения.
