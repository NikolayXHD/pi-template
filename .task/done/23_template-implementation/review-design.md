**M2. «Доставка в промпт из памяти, минуя чтение файлов» противоречит
reload-пути доставки.**

- design.md:208–210, 253–254: «содержимое промпта доставляется из памяти
  расширения, минуя чтение файлов» / «текст отдаётся из памяти расширения».
- design.md:226–228, 445–448: «по `/reload` — через перечитывание зеркал…»,
  «перечитыванием при `/reload`»; design.md:229–230: «Потребители вне промпта…
  обновляются перечитыванием».
- Расхождение: `/reload` — это именно чтение зеркал загрузчиком pi, а не
  доставка из памяти. Тезис описывает только путь «кнопка меню — точечная
  замена секций» и выдаёт частный случай за общий контракт секции
  «Лок-протокол»; зона B получит противоречивое описание.
  Починка — развести два пути: обычная доставка идёт из памяти заменой секций,
  при `/reload` — перечитыванием зеркал; лок в обоих путях не берётся.

**M3. Доставка применённой версии на старте сессии не обеспечена
перечисленными способами.**

- design.md:183–187 объявляет старт сессии применением («результат становится
  применённой версией»), design.md:445 — «Применение — только явное: старт
  новой сессии, `/reload`, кнопка», но способы названы только для `/reload` и
  кнопки (design.md:226–228, 446–448); для старта способ не назван.
- Факт кода: pi строит `_baseSystemPromptOptions` из данных загрузчика,
  прочитанных с диска до `session_start` (конструктор `AgentSession` →
  `_buildRuntime` → `_refreshToolRegistry`/`_setActiveTools`/
  `_rebuildSystemPrompt`; `bindExtensions` эмитит `session_start` уже после —
  `dist/core/agent-session.js`). Походовой промпт собирается из
  `_baseSystemPromptOptions` плюс мутации `before_agent_start` (`_prepareRun`);
  `reload()` есть только у командного контекста (`ExtensionCommandContext`),
  у контекста `session_start` его нет.
- Значит, рендер зеркал на `session_start` в первый ход не попадает (pi уже
  прочитал зеркала, возможно записанные другой сессией), а доставить свою
  версию можно только «точечной заменой секций» на `before_agent_start`. В
  дизайне это не сказано; тот же незакрытый путь у «сверки фактической модели
  перед первым ходом» (design.md:188–190).
- Последствие: первый LLM-ход может получить текст чужого view, что нарушает
  «Всё, что видит сессия, — её применённая версия» (design.md:450).
  Починка — назвать старт (и проверку модели) третьим случаем точечной замены
  секций на первом `before_agent_start`.

**M5. «Механизм детекции дочерней сессии не нужен» против принятой

## Сверено и совпало

- **`session_shutdown` при `/reload` до перечитывания.**
  `AgentSession.reload()` сначала эмитит `session_shutdown` с причиной
  `reload`, затем инвалидирует старый рантайм, перезагружает настройки и
  `ResourceLoader`; `session_start` с причиной `reload` приходит новому
  рантайму и только при наличии host-биндингов (`dist/core/agent-session.js`).
  Порядок из design.md:226–228 верен; набор причин `session_shutdown` —
  `"quit"|"reload"|"new"|"resume"| "fork"` (`dist/core/extensions/types.d.ts`).
- **`tool_execution_end` на всех финализациях.** Эмитится и на «immediate»
  путях (нет инструмента, ошибка валидации, блок `tool_call`, abort до
  `execute`), и после исполнения (в т.ч. усечённый ответ —
  `failToolCallsFromTruncatedMessage`); `tool_result` приходит только после
  `execute` через `finalizeExecutedToolCall` → `_afterToolCall`
  (`pi-agent-core/dist/agent-loop.js`, `dist/core/agent-session.js`).
  Вложенные `ctx.executeTool` идут теми же хуками и несут `parentToolCallId`.
  Формулировки design.md:263–265 и interview.md:437–441 совпадают; оговорка
  «зависший `execute` событий не даёт» верна.
- **`agents/*.md` читает pi-subagents, не pi.** `readAgentDefinitionFiles`
  (`fs.readFileSync`), кэш `agentDiscoveryCache` с отпечатком
  `file:${stat.size}:${stat.mtimeMs}`; `refreshAdvertisedAgents` на
  `session_start` (`clearAgentDiscoveryCache()` + `discoverAgents`), секция
  `advertised_subagents` — в `before_agent_start` (`src/agents/agents.js`,
  `src/extension/index.js`). design.md:108–110, 241–246 верны (кроме порядка,
  см. m1).
- **Спавн.** `buildEffectiveSystemPrompt` строится в процессе спавнящего
  (foreground `runs/foreground/execution.js`, background
  `runs/background/async-execution.js`, preflight `api/preflight.js`) и
  передаётся в launch-конфиг; тег `<active_agent name="…"/>` ставит
  `runs/shared/child-launch.js` (в `systemPrompt` при режиме replace, иначе в
  `appendSystemPrompt`), pane-native — `extension/herdr-pi-bridge.js` на
  `before_agent_start`. design.md:238–242, 374–377 верны.
- **`ctx.getSystemPrompt()` на `session_start`.** Контекст расширения:
  `getSystemPrompt: () => this.systemPrompt`; промпт собран в конструкторе
  `AgentSession` до `bindExtensions`, где эмитится `session_start`. Для
  in-process детей тег доступен уже на `session_start`.
- **Реестр обязательных расширений и machine.** Публичный
  `registerRequiredChildExtensions({sessionId, extensions:[{id, path[,
  requireForAllRunners]}]})` (`package.json`, export
  `./required-child-extensions`); `requireForAllRunners` опционален;
  `assertRequiredChildExtensionsAdmitted` отсекает не-native маршруты только
  при mandatory; `serializeHerdrPiLaunch` бросает при непустых
  `extensionPaths`/`requiredExtensions` («Pane-native remote Pi cannot transfer
  local extension paths…», `src/runs/shared/herdr-placed-run.js`).
  design.md:317–322 и В7 верны.
- **Handlebars 4.7.10** (зависимость pi-template `^4.7.10`): `{{vllm@}}` —
  parse error; `{{[vllm@]}}` и `{{[vllm@foo]}}` парсятся как путь с одной
  частью; `{{> ".pi/skills/x.md"}}` и `{{> (concat …)}}` парсятся; `{{>
  .pi/skills/x.md}}` — parse error. «Термины» (design.md:62–66) и В8
  совпадают.
- **Скилы, промпты, контекст.** Скилл-корень — по `SKILL.md`
  (`dist/core/skills.js`); промпты — `.md`-дети каталогов
  (`dist/core/prompt-templates.js`, `endsWith(".md")`); кандидаты контекста и
  обход предков cwd — `dist/core/resource-loader.js`. Ни одно из правил не
  видит `.template`.
- **`level`.** `ThinkingLevel` в pi-agent-core — `"off"|"minimal"|"low"|
  "medium"|"high"|"xhigh"|"max"`; `model` — `provider/modelId`.
  design.md:157–160 верен.
- **`PI_SUBAGENT_CHILD`** ставит фоновый раннер при импорте
  (`runs/background/subagent-runner.js`), у foreground-детей в процессе
  родителя его нет; формулировка design.md:338–339 этому не противоречит.
