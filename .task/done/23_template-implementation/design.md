# Дизайн — шаблонизация контекста (пакет pi-template)

## Цель

Заменить расширение roles обобщённым механизмом шаблонизации —
расширением pi, без правок кода pi. Любая переменная объявляется в
конфиге, шаблоны текстовых ресурсов ветвятся по значениям переменных,
значения берутся из машинного конфига или вычисляются shell-командой
из состояния мира. Шаблонизируются: глобальный и проектный контекст
(цепочка AGENTS.md, включая предков cwd), SYSTEM.md/APPEND_SYSTEM.md,
описания и тела скилов, кастомные промпты, промпты агентов
(`agents/*.md`).

Принцип полноты: шаблон разворачивается полноценно в каждой сессии,
включая дочерние сессии субагентов; нераскрытый контекст хуже
отсутствия фичи. Сценарии, неспособные развернуть шаблоны, не ломают
файлы и не отклоняются — пользователь предупреждается (см.
«Субагенты»).

Обоснования решений и отклонённые альтернативы — `interview.md`;
доказательная база (ревью реализуемости, исследование механизмов
pi-subagents) — `.task/done/22_generalized-template-variables/`.

## Термины

- **Переменная** — имя, опционально со списком допустимых значений;
  используется шаблонами в сравнениях `eq`/`in` и интерполяции. Значения —
  только строки для сравнения: контент через значения не проводится,
  интерполяция Handlebars не рекурсивна.
- **Машинное значение** — `initial` в `template.json`; сессия
  наследует его при старте.
- **Значение субагента** — `@` и `@<имя агента>` в `template.json`:
  чему равна переменная у субагента; `@<имя>` перекрывает `@`, без них
  субагент видит машинное значение, а вычисляемая переменная — своё
  вычисление.
- **Сессионное переопределение** — значение, установленное в сессии из
  меню команды расширения; в конфиг не пишется, живёт в записи сессии.
- **Вычисляемая переменная** — значение или список значений порождается
  shell-командой или берётся из окружения (`{"env": …}`); read-only,
  сессионное переопределение запрещено.
- **View** — полный набор значений всех переменных сессии: машинные
  значения, сессионные переопределения, неявные переменные (модель,
  уровень мышления), вычисляемые значения. Приоритет значения:
  сессионное переопределение выше машинного `initial`; для вычисляемых
  переменных (shell/env) переопределение невозможно — переданное на
  входе значение ошибка.
- **Источник** — файл `X.template` (каталог агента или проекта);
  единственный файл, который правится руками.
- **Target** — отрендеренная копия источника: файл `X` рядом с
  `X.template`, по общему для всех сессий пути; правится только
  перересовкой.
- **Партиал** — файл, подключаемый тегом `{{> имя}}`; имя — путь от корня
  своего каталога с расширением: агентские — от каталога агента
  (`roles/snippets/tests.md`), проектные — от корня проекта с
  префиксом `.pi/` (`.pi/skills/x/SKILL.md`). Каталоги заранее не
  обходятся: имя ищется на диске в тот момент, когда файл подставляется.
  Текст берётся из `X.template`, если он есть, иначе из самого `X`; имя
  при этом — в форме target, без
  суффикса `.template`. Пространства имён не
  пересекаются: имя уникально по построению. Статическая форма имени: путь без
  ведущей точки (`{{> roles/a.md}}`) или строковый литерал в кавычках
  (`{{> ".pi/skills/x.md"}}` — имена с точкой в начале без кавычек не
  разбираются парсером Handlebars).
- **Динамический партиал** — `{{> (concat "roles/" role ".md")}}`:
  имя собирается из значения переменной. На старте сессии расширение
  проверяет каждое значение из списка: файл для него есть или нет. Нет —
  предупреждение сразу, а не отказ в момент подстановки.
- **Квалификатор `@`** — обращение к значению переменной у субагента:
  `{{[vllm@]}}` (любой субагент) и `{{[vllm@foo]}}` (агент `foo`);
  легальны только в агентских файлах. Запись — штатное экранирование
  идентификатора Handlebars (стенографированный путь): `@` в
  идентификаторе парсер не берёт.
- **Секции промпта** — структурированные части системного промпта pi
  (`contextFiles`, `skills`, `customPrompt`, `appendSystemPrompt` и др.);
  pi сравнивает их по ходу и доставляет модели дельтой транскрипта.
- **Точечная замена секций** — применение версии контекста без
  перечитывания файлов: расширение отдаёт тексты секций из памяти в
  `before_agent_start`, pi доставляет их дельтой того же хода.
- **Фикс-точка** — состояние рендера шапки агентского файла, при котором
  проход с фактическими `model`/`level` даёт тот же текст; итерации
  прекращаются. `model@`/`level@` внутри выражений самой модели или
  уровня не сходятся — ошибка рендера.

## Архитектура

Механизм поставляется расширением pi. Сессия рендерит target своим
применённым view и держит их свежими; pi потребляет target нативно,
никаких путей не переопределяется. Публичный контракт расширения (имя
пакета, файлы конфига,
команды, записи сессии) — функциональные имена: движок шаблонов — деталь
реализации, его термина в контракте нет.

### Конвенция `X.template`

Источник — `X.template`; рядом генерируется target `X`. pi находит
target собственными средствами: кандидаты контекста — точные имена
(`AGENTS.override.md`, `AGENTS.md`, `AGENTS.MD`, `CLAUDE.md`,
`CLAUDE.MD`), скилл-корень определяется по `SKILL.md`,
промпты — `.md`-дети каталогов; файлы `.template` ни один из этих
механизмов не видит. Расширение не вкладывает ресурсы в pi и не
перехватывает обнаружение.

`roles/**` не генерируются: роль — управляемая шаблоном часть AGENTS.md
(динамический партиал), отдельного потребителя у файлов ролей нет —
как частиалы они доступны напрямую. Файлы с синтаксисом шаблона носят
имя `.md.template` — и роли, и сниппеты; имена ролей выводятся из имён
`.md.template`. Имя партиала при этом — в форме target:
`roles/develop.md` указывает на источник `roles/develop.md.template`.

Удаление `X.template` — отказ от шаблонного управления файлом, а не
удаление файла: `X` остаётся обычным файлом, его правка и удаление —
руками пользователя.

Frontmatter источника рендерится наравне с телом; отрендеренный файл с
frontmatter валидируется разбором YAML (описания скилов живут во
frontmatter); сбой валидации — провал рендера файла.

Свежесть target — совпадение его текста с рендером источника под view
применённой версии. Рендер детерминирован, отдельного отпечатка состояния нет:
target само по себе и есть кэш последнего успеха. Принадлежность `X` шаблону
определяется наличием `X.template`.

Генерируемые `X` появляются рядом со своими источниками — в каталоге
агента или в рабочем дереве проекта.

### Что pi читает само

- контекстные файлы, скилы, промпты, `SYSTEM.md`, `APPEND_SYSTEM.md` —
  target (нативное обнаружение); агентские файлы (`agents/*.md`) pi не
  обнаруживает — их читает pi-subagents (спавн и каталог
  advertised-агентов, см. «Лок-протокол»);
- `settings.json`, `models.json`, `auth.json`, `trust.json`, `mcp.json`,
  расширения, темы, пакеты (`git/`, `npm/`), каталог сессий — настоящие
  каталоги, без рендера.

Пакетные ресурсы (скилы и промпты пакетов из git/npm-чекаутов) не
шаблонизируются: легитимный `{{ }}` в стороннем контенте не трогается.

## Переменные и view

Объявление — в `template.json` (каталог агента):

```json
{
  "vars": {
    "role": {
      "values": {"shell": "basename -s .md roles/*.md"},
      "initial": "preflight",
      "@": "develop",
      "@plan": "design"
    },
    "vllm": {
      "values": ["on", "off"],
      "initial": "on"
    },
    "git_branch": {
      "initial": {"shell": "git rev-parse --abbrev-ref HEAD"},
      "cwd": "project"
    }
  }
}
```

- `values` — статический список или `{"shell": "…"}`; значения — строки
  stdout, по одной на строку, trim, пустые игнорируются, дубликаты
  схлопываются; ненулевой exit или таймаут (5 с) — предупреждение,
  переменная остаётся без списка значений.
- `initial` — строка, `{"shell": "…"}` или `{"env": "VAR"}` (lookup без
  exec и таймаута); вычисляемое `initial` даёт read-only переменную,
  переопределяемую только правкой конфига.
- `@`, `@<имя агента>` — значение переменной у субагента; задаются для
  любой объявленной переменной, их значение замещает и машинное, и
  вычисленное. При отсутствии обоих ключей субагент видит машинное
  значение, а вычисляемая переменная — своё вычисление.
- `cwd` — зона выполнения команды: `"agent"` (по умолчанию, каталог
  агента) или `"project"` (cwd сессии; у дочерних сессий — их
  собственный cwd).
- Переменные `model`, `level` не объявляются: неявные, read-only;
  объявление их в `template.json` — ошибка конфига. `model` —
  значение вида `provider/modelId` (`deepseek/deepseek-flash`), `level` —
  имя уровня (`off`…`max`).

Команды исполняются системным шеллом платформы (POSIX — `sh -c`, win32 —
`cmd.exe /c`) с фиксированным таймаутом 5 с. Строковая подстановка
значений в текст команды запрещена: значения доступны команде только
через окружение.

Окружение команды — окружение процесса плюс значения view, известные к
моменту запуска: неявные переменные, статическое `initial` и сессионные
переопределения (независимо от позиции объявления), вычисленные
переменные, объявленные раньше.

Имя переменной — имя env-переменной, алиас не вводится. Коллизия имени
переменной с именем в окружении процесса — ошибка конфига.

Вычисление идёт в порядке объявления; одна переменная не вычисляется
повторно, поэтому циклы ссылок невозможны по построению.

Линт предупреждает, если команда упоминает имя вычисляемой переменной,
объявленной позже; имена вне view (`$PATH` и т.п.) не трогаются.

Пересчёт и применение:

- старт сессии (startup, resume, new, fork) — полный view: машинные
  значения и сессионные переопределения (последнее значение из записей
  сессии на resume), `model`/`level` — по правилам выбора модели сессии
  (восстановление → дефолты настроек → provider-фолбэк), вычисляемые —
  своим вычислением; результат становится применённой версией контекста
  и доставляется точечной заменой секций на первом `before_agent_start`:
  pi читает target до `session_start`; без замены первый ход увидел бы
  текст чужого view;
- перед первым ходом — сверка фактической модели сессии: CLI-флаги в
  стартовый view не входят, поэтому на первом `before_agent_start`
  проверка перерисовывает view с фактической моделью и доставляет
  исправленную версию той же заменой секций до любого LLM-вызова;
- автоматических применений в течение сессии нет: контекст текущей
  сессии не обновляется сам никогда — ни правка исходника, ни другой
  ответ shell-команды не меняют промпт без явного действия (см.
  «Версии контекста сессии»);
- вычисляемые переменные считаются на старте сессии и по явным командам
  меню (одной переменной или всех), не автоматически;
- правка источника обнаруживается сверкой `mtime`+`size` на каждом
  `before_agent_start`; сверка не пересчитывает вычисляемые переменные —
  правка перерисовывает актуальную версию и помечает контекст
  устаревшим, промпт не меняется;
- подставлявшиеся при последней пересборке партиалы запоминаются по
  времени правки и размеру — вместе с парой `X.template`/`X`, включая
  случай «файла нет». Поэтому правка, появление и удаление любого из
  пары помечают контекст устаревшим;
- смена сессионной переменной и смена модели/уровня перерисовывают
  актуальную версию и помечают контекст устаревшим, но не применяют его;
- агентские файлы (`agents/**`) рендерятся двухэтапной перерисовкой без
  спавна (см. «Агентский файл»); на спавне файл перерисовывается со
  своими параметрами под локом.

## Лок-протокол

Target — общие файлы, и читают их потребители вне расширения: read tool
(тела скилов), pi-subagents (агентские файлы). Только такие чтения идут
под локом: расширение перерисовывает target под view применённой
версии, держит лок, пока читатель прочитает, и снимает его. Всё
остальное — без блокировок:
рендер идёт свободно, запись target атомарна, доставка содержимого
в промпт лок не берёт.

Форма чужого чтения:

1. взять лок на файл;
2. отрендерить источник под view применённой версии (см. «Версии
   контекста сессии»), провалидировать frontmatter;
   текст совпал с target — target не трогать, разошёлся — атомарная
   запись (временное имя плюс переименование);
3. прочитать (или дать прочитать) target;
4. снять лок.

Потребители и вставка лока:

- **доставка содержимого в промпт** (контекстные файлы, описания скилов,
  SYSTEM/APPEND): лок не берётся ни в одном из путей. Основная доставка —
  точечная замена секций из памяти расширения текстом применённой версии
  (применения: старт сессии и кнопка меню, см. «Версии контекста
  сессии»); `/reload` — частный случай, где target перечитывает сама pi
  (расширение пишет актуальную версию на `session_shutdown` с причиной
  `reload`, до перечитывания pi). Потребители вне промпта (slash-команды
  промпт-шаблонов, список `/skill:`) обновляются перечитыванием;
- **read tool** (тела скилов в середине хода): скобка из перехватов
  `tool_call` (лок + рендер + запись при расхождении) и
  `tool_execution_end` (снять лок); встроенный инструмент не
  переизобретается и не подменяется; вложенные вызовы (`executeTool`)
  проходят через те же перехваты;
- **спавн субагента** (агентский файл `agents/X.md`): скобка лока вокруг
  рендера и чтения; рендер двухэтапный (см. «Субагенты», «Агентский
  файл»), чтение шапки и промпта — под локом. Промпт ребёнка pi-subagents
  строится в процессе спавнающего (`buildEffectiveSystemPrompt`) и
  передаётся готовой строкой в конфиге запуска pi-subagents; чтение идёт
  через кэш агентов pi-subagents с отпечатком mtime/size — перезапись
  target даёт промах кэша;
- **каталог advertised-агентов** (шапки `agents/*.md`): pi-subagents
  перечитывает их на `session_start` и кладёт каталог в секцию промпта на
  каждом ходу — только пока активен инструмент `subagent`. Порядок
  обработчиков `session_start` между пакетами не гарантирован, чтение
  каталога асинхронное: каталог может держать прошлое target до
  следующего обновления; перерисовка target между двумя `session_start`
  в каталог не доходит.

Свойства лока:

- модель — пессимистичная: блокировка существует только ради чужих
  чтений из файла (read tool, pi-subagents); оптимистичная модель
  (отклонение коммита по изменившейся метке чтения) здесь неприменима —
  у чужого чтения нет коммита, который можно отклонить. Доставка в промпт
  конкуренции не знает: замена секций отдаёт текст из памяти расширения,
  перечитывание при `/reload` идёт без лока. Запись target конфликт не
  детектирует: атомарное переименование, оба варианта корректны,
  побеждает последний;
- межпроцессный (сессии живут в разных процессах: раннеры, отдельные
  окна pi); реализация — mkdir-лок или библиотечный, суть — файловая
  блокировка;
- повторно-входимый для одного процесса: параллельные вызовы read в
  одной реплике модели целятся в общие файлы и не должны глушить друг
  друга (счётчик глубины по пути);
- маркер владельца с временем и сброс протухших локов: точка снятия —
  `tool_execution_end`, он шлётся на всех финализациях вызова, включая
  прерванные и заблокированные (`tool_result` на них не приходит);
- владение всегда ограничено коротким таймаутом — на время рендера и
  чтения (секунды), независимо от длительности инструмента: долгий
  инструмент не держит лок дольше. Запись target и снятие лока — только
  при подтверждённом владении: утративший владение target не пишет и
  чужой лок не снимает, а повторяет перерисовку; зависший `execute`, не
  дающий событий, задерживает только свою попытку — лок протухает сам.

Разделение нагрузки: тела скилов отдаются только из файла — их читает
read tool, под локом; отдельного механизма отдачи тел из памяти нет.
Память участвует в промпте (контекст, описания скилов, SYSTEM/APPEND);
список `/skill:` и discovery UI остаются мимо — они из памяти загрузчика
и обновляются `reload`.

## Роль — динамический партиал

Роль не существует как понятие движка. AGENTS.md подключает текст роли
одной строкой:

```text
{{> (concat "roles/" role ".md")}}
```

Значения `role` — имена файлов-источников без расширения `.md.template`,
список порождается shell-командой; имя партиала строится в форме
target — `roles/<имя>.md`. Добавление роли сводится к созданию
файла-источника. Диспетчер
`{{#if (eq role "x")}}…` остаётся легальной, но не рекомендуемой формой.
Линт резолвит имя динамического партиала по конечной области значений
переменной: для каждого значения `concat` обязан дать имя существующего
партиала.

## Точка вставки — декларативная

Расширение ничего не дописывает в промпт. Где подключать роль или
любой другой контент, решает автор AGENTS.md партиалом.

## Субагенты

Требование: шаблоны полноценно разворачиваются в дочерних сессиях
субагентов — иначе задача шаблонизации теряет смысл. Расширение
регистрирует себя обязательным для всех дочерних сессий вызовом
`registerRequiredChildExtensions` (реестр обязательных расширений
pi-subagents на `sessionId`) — это цена механизма.

Вне процесса pi расширение не работает. Machine-размещения — pane-native
запуски Herdr на сохранённых машинах (`herdr-placed-run`, мост
`herdr-pi-bridge`): локальные пути расширений и обязательные расширения
туда не переносятся. Внешние CLI-агенты (`runner.type`
`external-cli`/`external-job`) — pi-сессии вовсе нет.

Файлы при этом не битые: target держат последний отрендеренный текст,
контекст связный (см. «Провал рендера»).

Известное ограничение pi-subagents: при зарегистрированном обязательном
расширении запуск на другую машину (`machine`) не стартует — сериализация
запуска отказывается нести локальные пути расширений
(`serializeHerdrPiLaunch`). Это поведение pi-subagents: расширение его не
обходит и не маскирует, регистрация нужна для детей в процессе pi;
встретилось — issue в pi-subagents.

Каждая сессия рендерит общие target своим применённым view:
переключение target между сессиями — штатное состояние, чужое чтение
под локом получает вариант применённой версии своей сессии.

Дочерняя сессия не получает переменных родителя: свои `model`/`level`,
свои сессионные переменные.

Роль — частный случай сессионной переменной: детская сессия стартует со
значения `@`/`@<имя>` конфига (без них — машинным `initial`), механизм
инициализации сессии в ней отрабатывает как в любой сессии (расширение
присутствует обязательно).

Чему равны значения переменных у субагентов — задают ключи `@` и
`@<имя>` конфига; незаданные ключи и вычисляемые переменные — общее
правило: машинное значение или вычисление. Пустые значения и env
`PI_SUBAGENT_CHILD` в вычисляемых — по-прежнему инструмент пользователя.

Своих механизмов детекции расширение не вводит: признак дочерней сессии —
тег `<active_agent name="…"/>` в её системном промпте, запасной — имя
сессии (см. «Агентский файл»; исследование — `research-child-identity.md`).

### Агентский файл: два этапа

Шаблон агентского файла рендерится в два этапа — и на спавне, и в
перерисовке без спавна: модель и уровень ребёнка определяются шапкой этого
же файла, поэтому до рендера шапки этих значений ещё нет.

Обычные ссылки на переменные в агентском файле берутся из view
применённой версии сессии (на спавне — сессии, устроившей спавн;
параметры спавна — поверх применённых значений). Значение переменной у
субагента заказывается квалификатором `@`: в файле агента `foo`
допустимы `{{[var@]}}` и `{{[var@foo]}}`, оба означают значение субагента
`foo` (ключ `@foo` конфига поверх `@`, иначе машинное значение).

Этап 1 — шапка. Рендер идёт итерациями до фикс-точки: первый проход —
с предварительными `model`/`level` (параметры спавна поверх дефолта
сессии), затем YAML отрендеренной шапки даёт фактические модель и
уровень ребёнка, и шапка перерендеривается с ними. Значения
`model@`/`level@` в шапке допустимы везде, кроме выражений самой модели
и уровня: повтор состояния при итерациях — ошибка рендера «модель шапки
зависит от `model@`».

Этап 2 — тело. Оно рендерится полным view будущего ребёнка: `model@` и
`level@` получают фактические значения этапа 1, кастомные `@`-переменные
— значения субагента из конфига, вычисляемые — в зоне ребёнка.

Потребителей агентского файла два основных: каталог advertised-агентов
(только шапка) и спавн (шапка и тело, со своими параметрами спавна);
preflight, slash-команды управления агентами и doctor читают те же
target атомарно. Перерисовка без спавна рендерит файл целиком тем же
кодом под view применённой версии: предварительные `model`/`level` —
дефолт сессии, фактические — из YAML шапки; спавн перерисовывает со
своими параметрами под локом.

Имя агента для `@`-подстановки расширение извлекает из системного промпта
ребёнка: pi-subagents публикует его тегом `<active_agent name="…"/>`
(читается на `session_start` у детей в процессе pi, на
`before_agent_start` — у pane-native). Запасной источник — имя сессии
ребёнка. Ни тега, ни имени сессии — сессия не субагент, `@`-ключи не
применяются. Тег есть, имя неизвестно — громкое предупреждение: `@` и
обычные ссылки работают, ключи `@<имя>` не применяются. Тег — внутренняя
конвенция pi-subagents, а не опубликованный контракт: расширение проверяет
его наличие и громко предупреждает об исчезновении (исследование каналов —
`research-child-identity.md`).

## Провал рендера

Потребитель получает из target либо корректный отрендеренный текст,
либо прежний успешный (кэш = содержимое target), либо ничего — сырых
тегов в промпт не бывает.

- провал рендера файла — target не переписывается, предупреждение
  называет источник и причину;
- target нет и рендер не удался: файла для потребителя нет — контекст
  выпадает из промпта, скил выпадает из списка, команда промпта не
  регистрируется, чтение скила даёт ошибку инструмента; предупреждение
  называет причину. Блокировать старт сессии расширение не может и не
  пытается: сигналом служит громкое предупреждение;
- битый `template.json` — view не строится, перересовка не происходит
  (прежние target остаются), предупреждение называет причину;
- отсутствие значений `model`/`level` — ошибка расширения,
  предупреждение, перересовка не происходит.

## Линт

Легальные формы: `{{#if (eq v "x")}}`, `{{#if (in v "a" "b")}}`, те же с
`{{#unless}}`, `{{else}}`, интерполяция `{{v}}`, партиалы статические и
динамические (`concat` из литеральных сегментов и переменных),
комментарии.

- необъявленная переменная — ошибка; переменная, объявленная без списка
  значений, легальна и в интерполяциях, и в сравнениях (литералы для неё
  не проверяются);
- литерал вне списка значений — предупреждение (список может быть
  устаревшим); уровень вне набора уровней мышления — предупреждение;
- динамический партиал по переменной без списка значений — ошибка
  (резолвить нечем);
- синтаксис шаблона во frontmatter разрешён (frontmatter рендерится, YAML
  проверяется после рендера);
- статический партиал — существование файла; строковая форма имени
  подчиняется тем же правилам, что форма-путь (без `..`, без абсолютных
  и обратных слэшей); динамический партиал — существование имени для
  каждого значения переменной из конечного списка;
- квалификатор `@` вне `agents/**` — ошибка; в `agents/foo.md`
  допустимы только `{{[var@]}}` и `{{[var@foo]}}`, прочие имена
  агентов — ошибка;

Линт идёт при старте и при сверке источников; результат — в
предупреждения UI.

## Записи сессии и resume

Смена переменной — запись `customType: "var"`, payload `{name, value}`.
Resume — последнее значение каждой переменной по её записям сверх
машинных значений конфига; `model`/`level` восстанавливает сам pi. Старт
новой сессии — машинные значения, переопределения с нуля. Записи старого
формата (`customType: "role"`) игнорируются.

## Версии контекста сессии

Расширение держит в памяти две версии набора файлов, влияющих на контекст
сессии: **применённую** — ту, что стоит в промпте и лежит в target на
диске, — и **актуальную** — перерисованную свежими исходниками и
значениями. Сама меняется только актуальная; расхождение двух версий —
это и есть «промпты отстали» в статусе.

Применение — только явное: старт новой сессии, `/reload`, кнопка в меню
команды расширения. Применение записывает актуальную версию в target и
доставляет её в память pi: старт и кнопка — точечной заменой секций на
`before_agent_start` (pi читает target до `session_start`; без замены
первый ход увидел бы текст чужого view), `/reload` — перечитыванием target
самой pi. После применения версии совпадают.

После `/reload` рантайм расширения заменён и память потеряна: новый
экземпляр принимает target за применённую версию (диск — источник
истины для применённого), актуальную рендерит заново.

Всё, что видит сессия, — её применённая версия: и промпт, и чужие чтения
её target. Исключение — агентский файл на спавне: поверх применённых
значений действуют параметры спавна (см. «Агентский файл»). Актуальная
существует для статуса и будущего применения.

## UI

Одна команда расширения — `/template` (В13) — открывает
исчерпывающий UX управления расширением:

- статус контекста сессии: промпты актуальны или устарели;
- значения переменных: для shell и env — возраст рассчитанного значения;
- смена сессионной переменной — контекст не обновляется, меняется только
  статус;
- перерасчёт указанной shell- или env-переменной;
- перерасчёт всех переменных;
- кнопка «обновить контекст текущей сессии» — применение;
- кнопка «применить всё и перечитать» — применение плюс `reload`:
  промпт-шаблоны pi раскрывает из памяти загрузчика, без перечитывания их
  текст не обновляется; скилы применяются и без перечитывания (описания —
  каждый ход, тела — чтением файла при вызове).

Статусная строка — один глиф состояния: `✓` контекст применён, `!` есть
не применённая пересборка, `‼` контекст не собран; цвет строки —
success/warning/error соответственно. Лишних слов в строке нет: строка
статуса общая для всех расширений. Переопределения сессии — компактно.
Листание значения переменной по кругу (механика `cycle` с
Ctrl+R) не переносится. Других команд расширение не даёт.

Язык интерфейса — английский, консистентно с pi: пункты меню, статус,
уведомления, предупреждения и ошибки. Esc в диалогах меню — шаг назад,
закрытие — только из корня меню.

## Миграция

- `roles.json` → `template.json`: стартовая роль (`default`) и список
  листания (`cycle`) уходят, появляются `initial` и `@`-ключи;
  стартовое значение роли — `initial` переменной `role`;
- источники переименовываются в `X.template`: глобальный
  `AGENTS.md.template` со строкой
  `{{> (concat "roles/" role ".md")}}`, `skills/**`, `prompts/**`
  и `agents/**` — свои файлы с `.template`; роли и сниппеты с синтаксисом
  шаблона тоже источники `X.template`, имена ролей — из имён `.md.template`;
- статические партиалы: имена путями от корня
  (`{{> tests.md}}` → `{{> roles/snippets/tests.md}}`);
- генерируемые `X` добавляются в `.gitignore` проектов;
- пакет `pi-roles` переименовывается в `pi-template`, правится
  `settings.json`; `roles/materialized/` удаляется;
- код движка (`vars`/`render`) переносится из экспериментального форка в
  пакет расширения; форк не нужен, его правки не требуются.

## План реализации

Работа идёт в пакете расширения. Зоны:

- **A. Движок** — `vars` (схема конфига, вычисление, окружение команд,
  каноническая сериализация) и `render` (грамматика, линт, партиалы,
  рендер) плюс тесты. Контракты —
  `.task/done/22_generalized-template-variables/spec-a-engine.md`
  (переносятся только `vars` и `render`; писатель контекстной директории
  из той спеки не нужен — его роль закрывает конвенция target).
- **B. Лок-протокол и точки потребления** — лок
  (межпроцессный, повторно-входимый, короткое владение), скобки
  `tool_call`/`tool_execution_end` (чужие чтения: read и спавн),
  обновление памяти pi (механизм по В10), пересчёт view (частота по В10).
- **C. UX и записи** — `/template`, статусная строка, записи `"var"`,
  resume, игнор записей `"role"`.
- **D. Миграция и документация** — конфиг, источники `.template`,
  `.gitignore`, settings.json, README/TESTING.

Проверка: тесты пакета в стиле существующих тестов, `probe`-сценарии
живого рендера; критерии приёмки пакетов — в спеках.

## Что не в этой итерации

- Шаблоны в запусках вне процесса pi (machine/pane-native Herdr, внешние
  CLI): best effort, без гарантий.
- Шаблонизация пакетных ресурсов и тем.
- Листание переменных (наследник cycle).
