## Поведение

### `vars.ts`

- **Конфиг `template.json`** (каталог агента): `vars` → имя переменной →
  `values` (статический список строк или `{"shell": …}`), `initial`
  (строка, `{"shell": …}`, `{"env": "VAR"}`), `cwd` (`"agent"` по
  умолчанию, `"project"`), `@` и `@<имя агента>` — только строки. Строгие
  ключи: неизвестный ключ, неизвестный верхний ключ, не-объект — ошибка.
  Имя переменной — идентификатор; коллизия с окружением процесса —
  ошибка; `model`/`level` неявные и не объявляются (`PI_SUBAGENT_CHILD` и
  детекция дочерней сессии не вводятся). Суффикс `@<имя>` проверяется
  формой `[A-Za-z0-9][A-Za-z0-9._-]{0,127}` — тот же класс, что у
  pi-subagents (`runs/shared/herdr-placed-run.js`).
- **Shell-контракт**: системный шелл платформы (`sh -c` / `cmd.exe /c`),
  таймаут 5 с (`SHELL_TIMEOUT_MS`), stdout построчно (trim, пустые
  игнорируются, дубликаты схлопываются), `initial` из shell — первая
  строка; ненулевой exit/таймаут — переменная без значения/списка плюс
  сообщение в `problems`; строковая подстановка в текст команды не
  делается.
- **Окружение команды**: окружение процесса + значения view, известные к
  моменту запуска — неявные, сессионные переопределения, значения
  субагента (`@`), статическое `initial`, lookup env (независимо от
  позиции объявления) и вычисленные переменные, объявленные раньше.
  Собственное значение команде не видно. Вычисление — в порядке
  объявления, повторных вычислений нет. Упоминание в команде более поздней
  вычисляемой переменной — предупреждение; имена вне view не трогаются.
- **Приоритеты**: сессионное переопределение (`implicit`) сильнее `initial`
  и значения субагента; переопределение вычисляемой (shell/env) — ошибка
  read-only, вычисленное значение остаётся.
- **Значения субагента**: `subagentValue(spec, agentName)` даёт цепочку
  `@<имя>` → `@`; `computeView` с `agentName` замещает и машинное, и
  вычисленное значение (shell-команда `initial` при этом не запускается);
  без ключей субагент видит `initial`/вычисление. `isComputedVariable`
  принимает необязательное имя агента: `@`-значение снимает
  read-only-природу.
- **Каноническая сериализация** `canonicalJson` (стабильный порядок
  ключей) сохранена — для сравнения view.

### `render.ts`

- **Грамматика** — порт словаря задачи 22 + квалификатор `@`: блоки
  `if`/`unless` над `eq`/`in`, интерполяция `{{v}}`, партиалы статические и
  динамические (`concat`), комментарии; всё прочее — ошибка.
- **Запись квалификатора** (решение supervisor, В1): стенографированный
  путь Handlebars — `{{[vllm@]}}` (любой субагент) и `{{[vllm@foo]}}`
  (агент `foo`). Сырая запись `{{vllm@}}` разбору не поддаётся (ID не
  допускает `@`); в сообщение о parse-error добавлена подсказка про
  `[vllm@]`. Незастёгнутая запись потребовала бы пре-лексера перед
  парсером с собственной поверхностью ошибок — зафиксировано как
  отклонённый вариант.
- **Линт квалификатора**: вне `agents/**` — ошибка; в `agents/foo.md`
  допустимы только `var@` и `var@foo`, чужое имя агента и имя не по форме —
  ошибка; `model@`/`level@` и формы с именем агента в шапке — ошибка.
  Линт агентского файла делит источник на шапку (frontmatter в конвенции
  pi: `---` в начале и закрывающая строка `---`) и тело и проверяет их
  раздельно: в теле `model@`/`level@` легальны.
- **Прочее из таблицы отказов**: динамический партиал по переменной без
  списка значений — ошибка; имя динамического партиала проверяется для
  каждого значения конечного списка; статические партиалы обоих корней
  (`roles/...` — путь, `.pi/...` — строковый литерал в кавычках) —
  существование; без `..`, абсолютных путей и обратных слэшей; литерал вне
  списка значений и уровень вне набора — предупреждение.
- **Рендер**: собственный environment, `knownHelpersOnly`, `noEscape`,
  `knownHelpers` — `eq` (строгое), `in` (последний options-аргумент
  отбрасывается), `concat`, `if`, `unless`; отсутствие партиала —
  исключение; рендер-функции линтуют вход и на проблему бросают.
- **Шов двух этапов**: `renderAgentHeader(source, ctx)` /
  `renderAgentBody(source, ctx)`; обычные ссылки — `parentView`, `@`-ссылки —
  `subagentView` (композиция в один плоский view с ключами `vllm@`,
  `vllm@foo`); `subagentView` — полный view будущего ребёнка (на спавне его
  считает зона B, в том числе `model`/`level` этапа 1). Разбор YAML — вне зоны
  A.

## Находки и решения по ходу

- **Порт shell-окружения**: в форке переопределение вычисляемой переменной
  (ошибка read-only) оставалось в `known` и попадало в окружение следующих
  команд, хотя значением view не является. Исправлено: при детекции
  переопределения имя удаляется из `known`/`view`, значение определяет
  вычисление (или остаётся пустым при провале). Добавлен регрессионный
  сценарий.
- **Шов двух этапов усилен**: `renderAgentHeader`/`renderAgentBody`
  бросают, если `@`-ссылка есть в источнике, а значения переменной в
  `subagentView` нет, — пропуск вызывающей стороны не даёт тихую пустоту.
- **Квалификатор в динамическом партиале** разрешён: линт резолвит имена
  по объявленному списку значений переменной (как для обычной ссылки),
  рендер подставляет значение субагента.
- **`partials` в контекстах**: линту значение не нужно (проверяется
  наличие), поэтому один тип `ReadonlyMap<string, string>`; для рендера —
  тексты, для линта по конвенции — пути источника; это задокументировано
  на интерфейсах `LintContext`/`RenderContext`.

## Остаточные риски и известные состояния

- **Типы не проверены компилятором**: в пакете нет `tsc`/tsconfig;
  корректность подтверждена исполнением под Node type-stripping и
  прогоном сценариев, синтаксических/типовых ошибок прогон не выявил.
- **BOM**: `splitAgentSource` повторяет конвенцию pi (`startsWith("---")`,
  поиск `\n---`), но, в отличие от `parseFrontmatter` pi, не снимает BOM —
  файл агента с BOM будет считаться без шапки. Край; при необходимости
  закрывается в зоне B.
- **Подсказка о `[var@]`** — эвристика (`hasRawQualifier`, регулярка по
  тексту тега), срабатывает только при ошибке разбора; в литералах внутри
  тегов возможен ложный хвост подсказки.
- **Предупреждение о поздней вычисляемой переменной** смотрит на
  объявленную природу `initial`, не на `@`-замещение для конкретного
  субагента, — это конфиг-линт, а не сессионный.
- **win32-ветка** `cmd.exe /c` тестами не исполнялась (нет платформы) —
  по коду; POSIX-ветка и реальный таймаут прогнаны на настоящем шелле.
- **`package.json`** — см. В3; **`TESTING.md`** описывает старую ролевую
  механику и вводит в заблуждение до зоны D.
