## Поведение

Источник истины — `design.md` задачи 23 (читать целиком, разделы
«Термины», «Переменные и view», «Линт», «Агентский файл: два этапа»).
Детали контракта shell-значений —
`.task/done/22_generalized-template-variables/spec-a-engine.md`.
При расхождении той спеки с design.md задачи 23 правит design.md.

Дельты к спеке A задачи 22 — их много, они собраны здесь:

1. Конфиг переменных — `template.json` в каталоге агента, не
   `handlebars.json`.
2. Поле `current` переименовано в `initial`; формы: строка, `{"shell"}`,
   `{"env"}`.
3. Новые ключи конфига `@` и `@<имя агента>` — значение переменной у
   субагента: только строки; замещают и машинное, и вычисленное; цепочка
   `@<имя>` → `@` → `initial`.
4. Неявные переменные — только `model`, `level`; `PI_SUBAGENT_CHILD` не
   существует, детекция дочерней сессии не вводится. Объявление `model`
   или `level` в конфиге — ошибка.
5. Грамматика получает квалификатор `@`: `var@` (значение любого
   субагента) и `var@<имя>` (конкретного). Линт: квалификатор только в
   `agents/**`; в `agents/foo.md` допустимы только `var@` и `var@foo`;
   `model@`, `level@` и их формы с именем агента — в шапке агентского
   файла ошибка.
6. Рендер агентского файла двухэтапный. Этап 1 — шапка: обычные ссылки
   берут view сессии-родителя, `@`-ссылки — значения субагента,
   `model@`/`level@` запрещены. Между этапами вызывающая сторона
   разбирает YAML и достаёт модель и уровень ребёнка — сам разбор YAML
   не входит в зону A. Этап 2 — тело: обычные ссылки — view родителя,
   `@`-ссылки — полный view субагента, где `model@`/`level@` получают
   фактические значения этапа 1, кастомные `@`-переменные — значения из
   конфига, вычисляемые — считаются в зоне ребёнка. Движок даёт шов
   между этапами; оркестрация спавна — зона B.
7. Каноническая сериализация view (стабильный порядок ключей) —
   остаётся, для сравнения view.
8. Значения субагента для вычисляемых переменных: `@`-ключ их замещает
   (строкой); без ключа субагент видит своё вычисление.

## Ловушки

- **`@` в идентификаторе Handlebars.** Сначала маленький прогон парсера:
  разбираются ли `var@` и `var@foo`. Не разбираются — не изобретать форму
  молча: ask через supervisor, термин `@` фиксирован, форма записи
  согласуется.
- **Партиалы.** Два корня: каталог агента (имя — путь от него,
  `roles/snippets/tests.md`) и проект (имя с префиксом `.pi/`,
  `.pi/skills/x/SKILL.md`). Статическая форма имени — путь без ведущей
  точки или строковый литерал в кавычках (имена с ведущей точкой без
  кавычек парсер не берёт). Без `..`, абсолютных и обратных слэшей.
  Динамический партиал (`concat`) — ошибка для переменной без списка
  значений; иначе имя должно существовать для каждого значения из
  конечного списка.
- **Хелперы.** `eq` сравнивает строго; у `in` последний аргумент —
  options хелпера, вырезать; рендер — собственный environment,
  `knownHelpersOnly`, `knownHelpers` включает `eq`, `in`, `concat`, `if`,
  `unless`; `noEscape: true`; отсутствие партиала при рендере —
  исключение, не тихая пустота.
- **Shell-контракт.** Системный шелл платформы (`sh -c` / `cmd.exe /c`),
  таймаут 5 с; stdout построчно, trim, пустые игнорируются, дубликаты
  схлопываются; ненулевой exit или таймаут — переменная без
  значения/списка плюс сообщение об ошибке в отчёте. Окружение команды —
  окружение процесса плюс значения view, известные к моменту запуска
  (неявные, `initial`, сессионные переопределения — независимо от позиции
  объявления, вычисленные, объявленные раньше); имя переменной — имя
  env-переменной; коллизия с именем из окружения процесса — ошибка
  конфига; строковая подстановка значений в текст команды запрещена.
  Вычисление в порядке объявления, повторных вычислений нет.
- **Стиль пакета.** Erasable TypeScript (без enum, namespace, parameter
  properties), без `any`, импорты с расширением `.ts`. Стиль соседних
  файлов — табуляция, docstring-комментарии по необходимости.
- **Тесты.** Данные заданы явно, предусловия и ожидания видны из текста;
  варианты одного сценария — параметризация внутри сценарного каркаса
  (или отдельные явные случаи — но без дублирования кода); имена без
  мусора. Каждый созданный сценарий прогнан.
- **Коммиты не делать** — закоммитит ведущий после ревью.
- **Инструменты.** Поиск — `git grep -in`; чтение — read с диапазонами;
  `git show` — `--stat`/`--name-only` либо с ограничением строк (`| head`).
  Долгих команд быть не должно, toolTimeoutMs 120 с.
- **Новые термины и имена в публичном контракте** — только из словаря
  design.md; нужен новый — ask.

## Критерии приёмки

- `node probe.mjs` из корня пакета — все сценарии зелёные.
- Тесты покрывают: разбор конфига (строгие ключи, формы `initial`,
  `@`-ключи, `cwd`, объявление `model`/`level` — ошибка); контракт
  shell-значений (stdout, exit, таймаут, окружение с view, коллизия имён —
  ошибка, порядок объявления); разрешение `@`-значений (цепочка
  `@<имя>` → `@` → `initial`, замещение вычисленных); таблицу отказов
  линта (`@` вне `agents/**`, чужое имя агента в `agents/foo.md`,
  `model@`/`level@` в шапке, динамические партиалы, переменные без
  списка значений, именование партиалов обоих корней); двухэтапный рендер
  агентского файла (шапка → модель/уровень → тело); детерминированность
  рендера и исключение на отсутствующем партиале; каноническую
  сериализацию.
- Отчёт — файл `report.md` рядом со спекой: файлы, поведение, команды
  проверки и их результаты, вопросы и возражения, поднятые по ходу.
