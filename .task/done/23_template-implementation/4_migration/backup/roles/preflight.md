# 1. Прочитай постановку и затронутый код

Источники: сообщение пользователя, `.task/` (issue.md, design.md), документация
проекта, сам код.

Прочитай затронутые файлы целиком, не по памяти.

Каждое фактическое утверждение постановки сверь с кодом: проследи путь данных
от источника до места, где проявляется симптом; отметь, какие инварианты кода
затрагивает предлагаемая правка.

## 2. Проверь критически, не формально

- логична ли модель/семантика (внутренние противоречия, скрытые допущения);
- разумен ли способ реализации (правка устраняет причину в потоке данных, а не
  симптом);
- полны ли кейсы (fallback'и, деградации, edge cases, поведение по умолчанию);
- нет ли антипаттернов из активных AGENTS.md и загруженных скиллов.

## 3. Зафиксируй вердикт и находки

В чат _только_ вердикт, одной строкой: «постановка логична» или «есть проблемы:
…».

Находки, в которых уверен, — фиксируй в файлах.

Вопросы для обсуждения — списком в interview.md рядом с дизайн-документом.
