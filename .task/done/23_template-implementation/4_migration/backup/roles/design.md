# Процесс дизайна

Дизайн до реализации, итерационный, с активным участием пользователя.

## Шаг 0: понимание проблемы

Прочитай код, с которого начинается задача (issue, проблемный файл), и
перескажи пользователю суть проблемы своими словами — коротко, без деталей
реализации. Убедитесь, что одинаково понимаете _что и зачем_, до того как
обсуждать _как_.

## Шаг 1: сбор дополнений

Собери у пользователя контекст, не выписанный в коде: бизнес-правила, модель
данных, constraints. Зеркаль каждое существенное дополнение — покажи, как оно
меняет твоё понимание задачи. Не двигайся дальше, пока пользователь не
подтвердит консистентность. Вопросы и ответы процесса веди в interview.md в
директории задачи.

## Шаг 2: карта территории

Составь ментальную карту кода, вовлечённого в задачу:

- какие модули/файлы задействованы
- как данные текут между ними (data flow)
- где точки расширения/вставки
- какие примитивы можно переиспользовать

Читай документацию (`docs/`) и trace'ируй вызовы (`git grep -in`). Пользователь
и агент видят один и тот же scope, без сюрпризов на этапе реализации.

## Шаг 4: черновик дизайна

По мере кристаллизации понимания — фиксируй инсайты в `design.md` в директории
задачи (`.task/current/NN_name/design.md` или
`.task/backlog/NN_name/design.md`).

Документ содержит разделы:

### 4.1. AS-IS: обзор механизмов

Текущий код в scope задачи: модули, связи, точки вставки — настолько детально,
чтобы обосновать дизайн-решение, без пересказа файлов.

### 4.2. Решения

Что и почему делаем или НЕ делаем; для каждой развилки — какие достойные
альтернативы остались.

### 4.3. Фолбэки

Каждый фолбэк (Optional-тип, дефолт, ветвление на отсутствие данных) — только
под конкретную проблему, которую решает, с записью об этом в документе.
Необоснованный фолбэк маскирует нарушенный инвариант вместо раннего падения.

### 4.4. План реализации

Конкретные шаги: какие файлы меняются, что добавляется, сигнатуры функций,
поток данных — детализация достаточна для реализации без повторного
исследования.

## Что не является дизайном

  постановку задачи.
