Перенеси все сессии pi из текущей директории в целевую директорию штатным
`pi --fork`.

Цель: промты worktree-fork и worktree-merge вместе предотвращают фрагментацию
истории сессий pi при работе в разных worktree. Этот промт выполняется из
worktree-сессии: он переносит ВСЕ сессии worktree (все `*.jsonl` в его папке
сессий) в основной проект, чтобы после удаления worktree история не осиротела и
была видна в `/resume` основного проекта. Работает и без git: если репозитория
нет, целевая директория задаётся аргументом.

Аргумент: $1

допустимые форматы:

- абсолютный путь: `/home/kolia/git/repo_name-pd`
- имя репозитория + суффикс: `repo_name-pd` (резолвится относительно родителя
  текущей директории)
- только суффикс: `-pd` (приклеивается к имени текущей директории)

Шаги:

1. Определи целевую директорию:
   - если аргумент передан — разреши его в абсолютный путь по форматам выше;
   - иначе — текущая директория должна быть linked worktree: первая строка
     вывода `git worktree list` — основная директория проекта. Если текущая
     директория — не linked worktree, остановись с ошибкой (передай целевую
     директорию аргументом).

2. Исходная папка сессий —
   `~/.pi/agent/sessions/--<кодированный путь текущей директории>--`, где
   кодированный путь — абсолютный путь без ведущего `/`, с `/` и `:`,
   заменёнными на `-`. Исходные файлы — все `*.jsonl` верхнего уровня этой
   папки. Если папки нет — сообщи и остановись.

3. Для каждого файла выполни из целевой директории:

   ```text
   pi --fork <id-сессии>
   ```

   id — из первой строки файла (header). Интерактивная сессия не откроется: у
   pi нет терминала, он создаст клон и завершится сам. Вывод команды (последнее
   сообщение сессии) — игнорируй.

4. Сообщи пользователю число перенесённых сессий и что они появятся в `/resume`
   целевой директории.
