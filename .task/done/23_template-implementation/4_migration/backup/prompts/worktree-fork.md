---
description:
  Создать worktree (или директорию без git) и перенести в него текущую сессию
  pi
---

Создай worktree и перенеси в него текущую сессию pi как форк. Если текущая
директория — не git-репозиторий, создай простую директорию (без git).

Цель: промты worktree-fork и worktree-merge вместе предотвращают фрагментацию
истории сессий pi при работе в разных worktree. fork создаёт изолированную
рабочую копию с собственной историей сессий, merge переносит эту историю
обратно в основной проект. Без merge история worktree-сессии осиротеет после
удаления worktree.

Аргумент ($1) — путь к worktree, один из форматов:

- абсолютный путь: `/home/kolia/git/repo_name-pd`
- имя репозитория + суффикс: `repo_name-pd` (резолвится относительно родителя
  текущей директории)
- только суффикс: `-pd` (приклеивается к имени текущей директории)

Шаги:

1. Разреши аргумент в абсолютный путь по форматам выше.

2. Создай директорию:
   - если текущая директория — внутри git-репозитория
     (`git rev-parse --is-inside-work-tree`), создай worktree, если его ещё
     нет:

     ```text
     git worktree add <путь> -b <суффикс без ведущего тире>
     ```

   - иначе — `mkdir -p <путь>`.

3. Выполни из новой директории:

   ```text
   pi --fork <id-текущей-сессии>
   ```

   id текущей сессии — `$PI_SESSION_ID`. Интерактивная сессия не откроется: у
   pi нет терминала, он создаст клон и завершится сам. Вывод команды (последнее
   сообщение сессии) — игнорируй.

4. Сообщи пользователю: путь, id новой сессии, что история живёт в
   `~/.pi/agent/sessions/--<кодированный путь>--` и сессию можно продолжить
   через `/resume` из новой директории; по завершении работы выполнить
   `/worktree-merge`, чтобы перенести историю обратно.
