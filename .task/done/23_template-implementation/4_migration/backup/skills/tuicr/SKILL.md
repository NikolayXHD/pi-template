## Наблюдение

```bash
python3 ~/.pi/agent/skills/tuicr/review.py --notify &
```

Запуск — только в фоне (`&`), из bash pi-сессии, где наследуется
`PI_INTERCOM_SESSION_ID`: полезного вывода для пользователя нотификатор
не даёт, панель ему не нужна. Нотификатор следит за всеми открытыми в
каталоге ревью (только локальными; PR-ревью — вне области скила) и
завершается сам, когда закрывается pi-сессия; на её перезапуск дан запас 5
минут. Повторный запуск в той же паре «каталог + сессия» возвращает 0 без
слежения — это не ошибка: процесс уже есть.

Сообщение приходит на каждое ревью. Внутри — блок на комментарий: строка
`[метка] адрес — текст` и под ней hunk-окно диффа (3 строки контекста, как в
TUI) или строка `ошибка: …`:

```text
[main/commits/6fa2151..6fa2151] src/a.py:12 + — вопрос
    @@ -3,8 +3,9 @@ l2
     l3
    >> +x
[main/commits/6fa2151..6fa2151] src/b.py:30 - — второй вопрос
    ошибка: не удалось собрать дифф-контекст: …
```

Адрес комментария — первая строка блока: сначала метка ревью в скобках,
затем адрес до «—». Метка — часть slug'а после `@`, она отличает ревью друг
от друга; в ответе копируется вместе с адресом. Строки после первой в блоке
(hunk или `ошибка:`) — продолжение, не новые комментарии.

Hunk-окно есть только в commit_range-ревью; в остальных источниках
(`working_tree`, `staged`, `staged_and_unstaged`, `pristine`, `*_and_commits`)
комментарии приходят без контекста. Строка `ошибка: …` — явный сбой
пересборки, не тихий пропуск: скажи о ней пользователю.

Уведомления о завершении ревью нет. Если нотификатор завершился сам (закрылась
pi-сессия или истёк запас), после перезапуска сессии его запускают заново;
не ушедшие комментарии достаются через `--list`. Код 1 на старте означает,
что сессия не числится в реестре брокера или брокер недоступен.

## Ответ

Отвечай на комментарии ревью только через ревью (`review.py --reply`).

Диалог по ревью не должен выплёскиваться в чат pi ни в каком виде, никаких
дополнений или пояснений в чат. Всё что касается ответа на комментарий в
ревью - пишется в ответный комментарий, и больше никуда.

Текст реплики пиши в файл и передавай ссылкой на него — shell не
участвует, экранировать ничего не нужно:

```bash
python3 ~/.pi/agent/skills/tuicr/review.py --reply <адрес> @<файл-текста>
```

Адрес: скопируй префикс первой строки блока дельты до « — » как есть (метка,
путь, номер строки и знак `+`/`-` — всё часть адреса).
Формы: `[метка] src/a.py:12 +` (добавленная строка),
`[метка] src/a.py:30 -` (удалённая), `[метка] src/a.py` (файл),
`[метка] review` (ревью целиком). Без метки адрес тоже принимается, но только
когда ревью в каталоге одно.

Простую однострочную строку можно передать и так: `"текст"`.

## Протокол правок по ревью

- Предложи решение
- Получи одобрение пользователя
- Вноси правки

## Посмотреть полный список комментариев

```bash
python3 ~/.pi/agent/skills/tuicr/review.py --list
```

Все живые ревью каталога, каждое со своей меткой, в порядке чтения; это же —
путь восстановления после самостоятельного выхода нотификатора.

## Оформление реплик

Изложение должно быть внятным, тезисы на отдельных абзацах.
