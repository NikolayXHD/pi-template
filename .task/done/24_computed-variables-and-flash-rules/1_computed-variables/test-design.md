# Дизайн тесткейсов: вычислимые переменные

Поведение — решения интервью (`interview.md`, часть 1): поле `compute` —
выражение значения (литерал, переменная, `concat`, условие как частный
случай `"true"`/`"false"`); `and`/`or`/`not` и булевы переменные в условиях
конфига и шаблонов; условие-переменная `{{#if is_flash}}`; пересчёт
производных при каждом изменении view; сессионное переопределение побеждает
вычисление; shell-вычисляемые остаются read-only.

Проверка — сценарии `probe.mjs` (движок, без процесса pi). Варианты одного
сценария — таблица внутри сценария.

Дизайн-ревью покрытия (subagent `reviewer`) — 17 находок, все внесены ниже;
находка 1 вскрыла баг (ссылка на недекларированную переменную в `compute`
проходила молча) — код исправлен, контракт записан в A4.

## A. Разбор `template.json`

- **A1. `compute` разобран.** Таблица форм: условие без внешних скобок
  (`in model "a" "b"`) и в скобках (`(in model "a" "b")`), литерал
  (`"flash"`), копия переменной (`is_flash`), склейка
  (`concat "modes/" mode ".md"`) — все загружаются без ошибок.
- **A2. `compute` не сочетается с `initial` и `values`.** Одна таблица по
  конфликтному ключу (`compute`+`initial`, `compute`+`values`) — ошибка
  конфига с именем переменной.
- **A3. Сломанное выражение — ошибка конфига.** Таблица: чужой хелпер
  (`frob x`), нехватка аргументов (`in`, `eq a`), лишнее значение (`eq a "b"
  "c"`), `not` без операнда (`(not)`) и с двумя, не-литерал в сравнении
  (`eq a b`), хеш-аргументы (`(eq a="b")`), `concat` без сегментов,
  условие операндом `concat` (`concat (eq a "b")`), пустая строка, мусор
  (`a b (`), `compute` не строка (`42`) — ошибка с именем переменной.
- **A4. Ссылки выражения — переменные.** Таблица: ссылка на недекларированную
  переменную — ошибка «unknown variable» с обоими именами; ссылка на
  переменную, объявленную позже, — ошибка «declared earlier»; самоссылка —
  та же ошибка; ссылка на неявную `model`/`level` — допустима.

## B. Вычисление view

- **B1. Значение и список.** `is_flash` = `in model "a" "b"`: при
  `model: "a"` view даёт `"true"`, при `model: "c"` — `"false"`;
  `values.is_flash` — `["true", "false"]`.
- **B2. Составное выражение и цепочка производных.** `is_dumb` =
  `or is_flash (eq level "off")`: таблица входов (`model`, `level`) →
  ожидаемые `"true"`/`"false"`; производная `is_dumb` следует за `is_flash`
  в порядке объявления.
- **B3. Переопределение побеждает.** Вход `is_flash: "false"` при вычислимом
  `"true"`: view `"false"`, проблем нет (в отличие от shell/env read-only).
  Дополнительно: переопределение и `@`-значение одновременно — вход побеждает.
  Строка вне `{"true", "false"}` — ошибка, значение — результат выражения.
- **B4. `@`-значение побеждает вычисление.** `@: "false"`, `agentName: "foo"`:
  view `"false"`. Строка вне `{"true", "false"}` — ошибка конфига.
- **B5. Литералы вне списков — предупреждения.** `eq role "z"` (список
  `["a", "b"]`) — предупреждение о списке; `eq level "ultra"` — об уровне
  мышления; два литерала вне списка — два предупреждения, дубликат
  (переменная + значение) схлопывается.
- **B6. Сломанное выражение в hand-built конфиге** — проблема и пустое
  значение (стадия вычисления, не разбора).
- **B7. `evaluateExpressions` пересчитывает производные.** После смены
  `model` во view производная пересчитана; переопределённая переменная
  сохраняет значение; выражение, которое не разбирается, — значение не
  меняется, без исключений.
- **B8. Строковая производная.** `mode_file` = `concat "modes/" mode ".md"`:
  view даёт склейку; копия переменной (`compute: "is_flash"`) даёт значение
  источника; список значений: у булевой производной `["true", "false"]`, у
  строковой — без списка (lint литералов её не сверяет).
- **B9. Пустые значения.** Переменная со значением `""` (неудавшийся shell):
  `eq x ""` — истина, `in x ""` — истина, голое `x` — ложь.
- **B10. Shell/env остаются read-only** — покрыто существующим сценарием
  `when_override_of_computed_then_problem_and_computed_value`; новых
  проверок не требуется.

## C. Грамматика шаблонов и линт

- **C1. Новые законные формы.** Таблица: `{{#if is_flash}}`, `{{#unless
  is_flash}}`, `(not is_flash)`, `(or is_flash (eq level "off"))`, `(and (in
  model "a") (not (eq level "off")))`, `or` из трёх операндов.
- **C2. Новые отказы.** Таблица: `or`/`and` без операндов, `not` с двумя,
  литерал операндом (`(or "x")`), чужой хелпер вложенный (`(and (frob role))`),
  недекларированный операнд, голое имя не-булевой переменной (`{{#if role}}`
  при списке `["a", "b"]` — переименовать существующий пункт «bare path in a
  condition»), `eq` с лишним значением, хеш в условии.
- **C3. Квалифицированный операнд.** Arrange явно: переменная `flag` со
  списком `["true", "false"]` и `vllm` с тем же списком; в файле агента
  `{{#if (or [flag@] vllm)}}` проходит (список переменной — критерий
  булевости), вне файлов агента — отказ по правилу квалификаторов.

## D. Рендер: правда и ложь

- **D1. Условие-переменная.** Таблица `{{#if is_flash}}A{{else}}B{{/if}}`:
  `"true"` → `A`; `"false"`, `""`, `"TRUE"`, `"yes"` → `B` (истина только
  точное `"true"`); зеркало для `{{#unless}}` и `(not …)`.
- **D2. Связки.** Таблица `is_flash` × `level` для `(or …)`, `(and …)` —
  ожидаемая ветка; `eq`/`in` на булевой переменной — сравнение строк.
- **D3. Интерполяция.** `{{is_flash}}` печатает `true`/`false` (строковое
  значение view).

## E. Жизненный цикл сессии

- **E1. Смена модели пересчитывает производную.** Сессия стартует с `is_flash`
  от `model`; `onModelChanged` на flash-модель → `currentView().is_flash ===
  "true"` без явного пересчёта; корректировка фактической модели на первом
  ходу (`checkActualModel`) — та же производная следует за моделью.
- **E2. Переопределение вычислимой переменной.** `setVariable("is_flash",
  "false")` — ok (в отличие от shell-вычисляемой — отказ), значение во view
  `"false"`, производная, зависящая от неё, пересчитана.
- **E3. Дочерние view.** Вычисление view для `agentName` с моделью ребёнка
  выводит `is_flash` из модели ребёнка; вычислимая переменная с
  `@`-значением сохраняет его при `onModelChanged` родителя.

## F. Меню и пересчёт

- **F1. Строка вычислимой переменной.** `variableFacts`: `computed: false`
  (возраста нет), `values: ["true", "false"]`, `overridden: true` при
  переопределении — строка редактируется, как обычная.
- **F2. Пересчёт одной переменной.** `recompute("is_flash")` — отказ «is not
  computed — nothing to recompute» (пересчитывать нечего: выражение чистое);
  `recomputeAll` производную пересчитывает.

## Не покрывается сценариями `probe.mjs`

Доставка контекста и поведение меню в живой сессии pi — ручной прогон:
`is_flash` в `template.json`, `{{#if is_flash}}` в шаблоне, смена модели →
контекст устарел → применение → блок правил появляется/исчезает вслед за
моделью; переключение `is_flash` в меню.

## Решение (находка ревью 2)

Значение булевой производной вне `{"true", "false"}` — ошибка (решение 1.4
интервью): вход переопределения и `@`-значение вне домена отклоняются,
значение остаётся результатом выражения. Проверка в трёх точках: разбор
конфига, построение view, `setVariable`. Для строковых производных домена
нет — вход принимается как есть.
