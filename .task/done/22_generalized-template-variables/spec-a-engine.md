## Поведение

### vars.ts

- Разбор `handlebars.json` (каталог агента): строгие ключи, неизвестный
  ключ — ошибка; на каждый файл — одна структура `vars`.
- Переменная: `values` (статический список строк или `{"shell": …}`),
  `current` (строка, `{"shell": …}`, `{"env": "VAR"}`), `cwd`
  (`"agent"` по умолчанию, `"project"`).
- Shell-контракт: команды исполняются системным шеллом платформы
  (POSIX — `sh -c`, win32 — `cmd.exe /c`); stdout построчно, trim,
  пустые игнорируются, дубликаты схлопываются; ненулевой exit или
  таймаут 5 с — переменная без списка/значения плюс сообщение об
  ошибке в отчёте (вызывающая сторона показывает предупреждение).
- Окружение команды: окружение процесса плюс значения view, известные
  к моменту запуска — неявные, статический `current` и сессионные
  переопределения (независимо от позиции объявления), вычисленные
  переменные, объявленные раньше; имя переменной — имя env-переменной.
  Коллизия имени переменной с именем из окружения процесса — ошибка
  конфига. Строковая подстановка значений в текст команды запрещена.
- Вычисление в порядке объявления в конфиге; повторных вычислений нет
  (циклы невозможны по построению). Упоминание в команде имени
  ВЫЧИСЛЯЕМОЙ переменной, объявленной позже, — предупреждение линта;
  имена вне view (`$PATH` и т.п.) не трогаются.
- `{"env": …}`: сырое значение процесса, отсутствующее — пустая строка,
  без exec и таймаута. Вычисляемое `current` (shell/env) — read-only
  (вызывающая сторона запрещает переопределение).
- Неявные значения `model`, `level`, `PI_SUBAGENT_CHILD` приходят
  входом; их извлечение из контекста сессии — вне пакета.
- Каноническая сериализация (стабильный порядок ключей) — для
  `variables.json` и сравнения view.

### render.ts

Грамматика и линт — по разделу «Линт» design.md. Словарь: блоки
`if`/`unless` над условиями `eq`/`in`, интерполяция `{{v}}`, партиалы
статические и динамические (`concat` из литеральных сегментов и
переменных), комментарии; всё прочее — ошибка линта. Пути-переменные —
любые объявленные переменные (не только `model`/`level`).

Ловушки переноса:

- регистр партиалов — только включаемые поддеревья: агент — `roles/**`,
  `skills/**`, `prompts/**`; проект — `.pi/skills/**`, `.pi/prompts/**`;
  файлы-входы (цепочка AGENTS.md, SYSTEM.md, APPEND_SYSTEM.md) в
  регистр не входят (они рендерятся в зеркало как источники контекста);
  имя — путь от корня своего каталога (проектные — с префиксом `.pi/`),
  уникальность имени по построению, проверки одноимённости нет;
  для динамического партиала — существование имени для каждого
  значения переменной из конечного списка значений; для переменной
  без списка значений динамический партиал — ошибка;
- frontmatter рендерится наравне с телом; синтаксис шаблона в нём
  легален; YAML-валидация отрендеренного файла — в context-dir.ts;
- параметры хелперов: последний аргумент — options хелпера, для `in`
  его вырезать; `eq` сравнивает строго;
- рендер: собственный environment, `knownHelpersOnly`, `knownHelpers`
  включает `eq`, `in`, `concat`, `if`, `unless`; `noEscape: true`;
- отсутствие партиала при рендере — исключение (политика вызывающей
  стороны), не тихая пустота.

### context-dir.ts

Писатель контекстной директории и перечень источников.

- Перечень источников (проверка на временных каталогах):
  - каталог агента: `AGENTS.md`, `SYSTEM.md`, `APPEND_SYSTEM.md`,
    `skills/**`, `prompts/**`; `roles/**` — в регистр партиалов,
    в зеркало не входит;
  - каталог проекта: цепочка контекстных файлов — вызовом
    `loadProjectContextFiles` самого форка (приоритет имён кандидатов
    и worktree-механику не переизобретать); `.pi/SYSTEM.md`,
    `.pi/APPEND_SYSTEM.md`, `.pi/skills/**`, `.pi/prompts/**`.
- Зеркало: `*.md` из перечня рендерятся, остальные файлы — симлинки
  на источники; путь в зеркале — абсолютный путь источника без ведущего
  разделителя.
- `manifest.json`: источник → отрендеренный файл, ошибки рендера;
  `variables.json`: канонический view. Сессионный маркер — вне пакета.
- `*.md` с frontmatter после рендера валидируются разбором YAML
  (parseFrontmatter форка); сбой — файл не пишется, ошибка в манифест.
- Атомарность: временный файл плюс переименование; неизменившийся
  текст не переписывается.
- Провал рендера файла — прежнее содержимое не трогается (это и есть
  кэш последнего успеха), ошибка попадает в манифест.
