## Результат и поведение

### 1. Стартовый рендер — до первой загрузки ресурсов

View строится из: машинных значений `handlebars.json`; сессионных
переопределений — из записей `customType: "var"` открытой сессии
(последнее значение переменной; записи `"role"` игнорируются);
`model`/`level` — по правилам выбора модели сессии: восстановление →
дефолты настроек → provider-фолбэк (`findInitialModel`, та же логика,
что в создании сессии); CLI-флаги в стартовый view не входят —
проверка перед первым ходом перерисовывает view с фактической
моделью до любого LLM-вызова; неявных значений. Затем `writeContextDir`
— и только потом загрузка ресурсов pi.

Формат значений: `model` — `provider/modelId`, `level` — имя уровня
(`off`…`max`).

Отсутствие `model`/`level` — ошибка движка, старт невозможен.
Битый `handlebars.json` — старт невозможен (кэша у свежей сессии нет);
при resume с прошлым зеркалом — зеркало не трогается, старт
продолжается с предупреждением (design, «Провал рендера»).

### 2. Загрузка ресурсов из контекстной директории

Перечень шаблонизируемых ресурсов — по `listSources`/манифесту пакета A.
Из зеркала читаются: контекстные файлы (цепочка AGENTS.md), скилы
(описания и тела; `filePath` скила — путь зеркала), промпт-шаблоны,
`SYSTEM.md`/`APPEND_SYSTEM.md`. Пути, попадающие в промпт (атрибут
`path`, location скила) — пути контекстной директории.

Не трогаются (читаются из настоящих каталогов): пакетные ресурсы,
темы, расширения, `settings.json`, `models.json`, `auth.json`, `mcp.json`,
`agents/*.md`, каталог сессий. Инвариант: вне перечня источников
ничего не перенаправляется.

### 3. Обновления

Перед каждым ходом: пересчёт вычисляемых переменных, сверка источников
(mtime+size файлов перечня), проверка `model`/`level`. View или
источники изменились — перересовка `writeContextDir` плюс полная
перезагрузка ресурсов (штатный reload: расширения перечитываются —
принять, события редкие). Без изменений — ничего. То же по событиям:
смена модели/уровня, смена переменной (вызывается из `/var`, пакет C).

### 4. Защита зеркала

`edit`/`write` (и удаление) по путям контекстной директории — ошибка
инструмента с путём источника из манифеста: правится источник, зеркало
перерисовывается.

### 5. Субагенты и марка сессии

Каждая сессия строит свою контекстную директорию своим view (тот же
код, без ветвления на «дети»). Неявная `PI_SUBAGENT_CHILD` = `"1"`:
env `PI_SUBAGENT_CHILD`, или env `PI_HERDR_MODE`, или сессия не основная.
Марка основной сессии: `src/main.ts` помечает создаваемые им сессии
любого режима (interactive, print, rpc) — включая переключения
`/new`, `/resume`; сессии, созданные SDK, марки не получают. У
print/rpc-сессий `PI_SUBAGENT_CHILD` = `""` — они не субагентские.

Сессионный маркер контекстной директории: файл с id сессии в каталоге
`<каталог сессии>/context/`; несовпадение при следующем открытии —
предупреждение (требование «1 директория = 1 сеанс»). Для in-memory
сессий — временный каталог, чистка на завершении.

### 6. Жизненная сила кэша

Содержимое зеркала — и есть кэш последнего успеха: провал рендера
файла не трогает его прежний текст; отсутствующий в зеркале файл
пишется в ошибки манифеста. Отдельного кэша не делать.

## Ловушки

- `loadProjectContextFiles` — источник перечня цепочки (не
  переизобретать обход и worktree-механику).
- Reload ресурсов — штатный механизм pi; не изобретать частичный.
- Модель/уровень на старте могут отличаться от итоговых (пользователь
  переключит после старта) — их смена обязана вызывать обновление (п. 3).
- Записи сессии читаются как есть: незнакомый `customType` игнорируется.
- Термины: глоссарий design.md («зеркало» — термин, согласован);
  новые имена — ask.
- Правила форка `/home/kolia/git/pi/AGENTS.md` (как в спеке A):
  erasable TS, без `any` и inline imports, `npm run check` после правок,
  коммиты не делать; поиск — только `git grep -in`, чтение — read с
  диапазонами.

## Критерии приёмки

- `npm run check` чисто; тесты в конвенциях форка, каждый созданный —
  прогнан.
- Тесты покрывают: стартовый рендер до загрузки (view из записей и
  настроек), чтение ресурсов из зеркала и пути в промпте, обновление по
  сверке источников/вычисляемых/модели, битый конфиг (отказ стартовать
  без кэша; неприкосновенность зеркала с кэшем), ошибку edit/write по
  путям зеркала с путём источника, значения `PI_SUBAGENT_CHILD` по
  трём признакам, сессионный маркер.
- Отчёт: файлы, поведение, команды проверки и результаты, вопросы.
