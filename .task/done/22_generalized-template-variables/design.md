# Дизайн — 22 шаблонизация контекста (расширение pi)

## Цель

Заменить расширение roles обобщённым механизмом шаблонизации —
расширением pi, без правок кода pi (форк отменён, §16). Любая
переменная объявляется в конфиге, шаблоны текстовых ресурсов ветвятся
по значениям переменных, значения берутся из машинного конфига или
вычисляются shell-командой из состояния мира. Шаблонизируются:
глобальный и проектный контекст (цепочка AGENTS.md, включая предков
cwd), SYSTEM.md/APPEND_SYSTEM.md, описания и тела скилов, кастомные
промпты, промпты агентов (`agents/*.md`).

Развилки обсуждены в `interview.md` (§13–16 — история с форком и её
отмена), ссылки — по номерам разделов ответов.

## Термины

- **Переменная** — имя со списком допустимых значений; используется
  шаблонами в сравнениях `eq`/`in` и интерполяции. Значения — только
  строки для сравнения: контент через значения не проводится,
  интерполяция Handlebars не рекурсивна.
- **Машинное значение** — `current` в `handlebars.json`; сессия
  наследует его при старте.
- **Сессионное переопределение** — значение, установленное в сессии
  командой `/var`; в конфиг не пишется, живёт в записи сессии.
- **Вычисляемая переменная** — значение или список значений порождается
  shell-командой; read-only, сессионное переопределение запрещено.
- **View** — полный набор значений всех переменных сессии: машинные
  значения, сессионные переопределения, неявные переменные (модель,
  уровень мышления), вычисляемые значения.
  Приоритет значения: сессионное переопределение выше машинного
  `current`; для вычисляемых переменных (shell/env) переопределение
  невозможно — переданное на входе значение ошибка.
- **Источник** — файл `X.template` (каталог агента или проекта);
  единственный, что правится руками.
- **Зеркало** — отрендеренная копия источника: файл `X` рядом с
  `X.template`, по общему для всех сессий пути; правится только
  перересовкой.
- **Партиал** — файл, подключаемый тегом `{{> имя}}`; имя — путь от
  корня своего каталога с расширением: агентские — от каталога агента
  (`roles/snippets/tests.md`), проектные — от корня проекта с префиксом
  `.pi/` (`.pi/skills/x/SKILL.md`). Пространства имён не пересекаются:
  имя уникально по построению. Статическая форма имени: путь без
  ведущей точки (`{{> roles/a.md}}`) или строковый литерал в кавычках
  (`{{> ".pi/skills/x.md"}}` — имена с точкой в начале без кавычек не
  разбираются парсером Handlebars).
- **Динамический партиал** — `{{> (concat "roles/" role ".md")}}`:
  имя партиала резолвится подвыражением по значению переменной.

## Архитектура

Механизм — расширение pi. Сессия рендерит зеркала под своим view и
держит их свежими; pi потребляет зеркала нативно, никаких путей не
переопределяется.

### Конвенция `X.template`

Источник — `X.template`; рядом генерируется зеркало `X`. pi находит
зеркала собственными средствами: кандидаты контекста — точные имена
(`AGENTS.md`, `CLAUDE.md`), скилл-корень определяется по `SKILL.md`,
промпты — `.md`-дети каталогов; файлы `.template` ни один из этих
механизмов не видит. Расширение не вкладывает ресурсы в pi и не
перехватывает обнаружение.

`roles/**` не генерируются: роль — управляемая шаблоном часть
AGENTS.md (динамический партиал), отдельного потребителя у файлов
ролей нет, в реестр партиалов они входят как есть.

Frontmatter источника рендерится наравне с телом; отрендеренный файл с
frontmatter валидируется разбором YAML (описания скилов живут во
frontmatter); сбой валидации — провал рендера файла.

Штамп свежести — скрытый файл рядом с зеркалом (`X` плюс отпечаток:
канонический view и mtime+size источника); без совпадения штампа
зеркало считается устаревшим.

Генерируемые `X` появляются в рабочем дереве проекта рядом с
шаблонами.

### Что pi читает само

- контекстные файлы, скилы, промпты, промпты агентов (`agents/*.md`),
  `SYSTEM.md`, `APPEND_SYSTEM.md` — зеркала (нативное обнаружение);
- `settings.json`, `models.json`, `auth.json`, `trust.json`,
  `mcp.json`, расширения, темы, пакеты (`git/`, `npm/`), каталог
  сессий — настоящие каталоги, без рендера.

Пакетные ресурсы (скилы и промпты пакетов из git/npm-чекаутов) не
шаблонизируются: легитимный `{{ }}` в стороннем контенте не трогается.

## Переменные и view

Объявление — в `handlebars.json` (каталог агента):

```json
{
  "vars": {
    "role": {
      "values": {"shell": "basename -s .md roles/*.md"},
      "current": "preflight"
    },
    "vllm": {
      "values": ["on", "off"],
      "current": "on"
    },
    "git_branch": {
      "current": {"shell": "git rev-parse --abbrev-ref HEAD"},
      "cwd": "project"
    }
  }
}
```

- `values` — статический список или `{"shell": "…"}`; значения — строки
  stdout, по одной на строку, trim, пустые игнорируются, дубликаты
  схлопываются; ненулевой exit или таймаут (5 с) — предупреждение,
  переменная без списка.
- `current` — строка, `{"shell": "…"}` или `{"env": "VAR"}` (lookup
  без exec и таймаута); вычисляемое `current` даёт read-only
  переменную, переопределяемую только правкой конфига.
- `cwd` — зона выполнения команды: `"agent"` (по умолчанию, каталог
  агента) или `"project"` (cwd сессии; у дочерних сессий — их
  собственный cwd).
- Переменные `model`, `level` не объявляются: неявные, read-only;
  объявление их в `handlebars.json` — ошибка конфига. `model` —
  значение вида `provider/modelId` (`deepseek/deepseek-flash`),
  `level` — имя уровня (`off`…`max`).

Окружение shell-команд: системный шелл платформы (POSIX — `sh -c`,
win32 — `cmd.exe /c`, таймаут 5 с фиксированный). Окружение команды —
окружение процесса плюс значения view, известные к моменту запуска:
неявные переменные, статический `current` и сессионные переопределения
(независимо от позиции объявления), вычисленные переменные,
объявленные раньше. Имя переменной — имя env-переменной (алиас не
вводится, §10). Коллизия имени переменной с именем в окружении
процесса — ошибка конфига. Вычисление — в порядке объявления; одна
переменная не вычисляется повторно, поэтому циклы ссылок невозможны
по построению. Линт предупреждает, если команда упоминает имя
вычисляемой переменной, объявленной позже; имена вне view (`$PATH`
и т.п.) не трогаются. Строковая подстановка значений в текст команды
запрещена.

Частота пересчёта view:

- старт сессии (startup, resume, new, fork) — полный view: машинные
  значения и сессионные переопределения (последнее значение из
  записей сессии на resume), `model`/`level` — по правилам выбора
  модели сессии (восстановление → дефолты настроек → provider-фолбэк;
  CLI-флаги в стартовый view не входят — проверка перед первым ходом
  перерисовывает view с фактической моделью до любого LLM-вызова),
  вычисляемые — своим вычислением. Дальше — пересчёт и перересовка
  зеркал по конвенции ниже;
- каждый ход — пересчёт вычисляемых и сверка источников (mtime+size
  шаблонных файлов); view изменился или источники правились —
  перересовка;
- смена переменной (`/var`) и смена модели/уровня — немедленная
  перересовка.

## Лок-протокол

Чтение любого шаблонизируемого файла идёт под локом с проверкой
свежести. Единая форма для всех потребителей:

1. взять лок на файл;
2. зеркало устарело (штамп не совпадает с view сессии или источником) —
   рендер источника под view сессии, валидация frontmatter, атомарная
   запись зеркала и штампа (временное имя плюс переименование);
3. прочитать (или дать прочитать) зеркало;
4. снять лок.

Потребители и вставка лока:

- **загрузка ресурсов pi** (контекстные файлы, описания скилов,
  промпты, SYSTEM/APPEND): расширение держит лок вокруг «рендер +
  запись + перечитывание» (`reload`); перечитывание — единственный
  путь доставить содержимое в память pi, момент чтения выбирает pi;
- **read tool** (тела скилов в середине хода): скобка из перехватов
  `tool_call` (лок + рендер-если-устарело + запись) и `tool_result`
  (снять лок); встроенный инструмент не переизобретается и не
  подменяется; вложенные вызовы (`executeTool`) проходят через те же
  перехваты;
- **спавн субагента** (промпт агентского файла `agents/X.md`): скобка
  лока вокруг построения промпта; рендер — view'ом сессии-получателя
  (ребёнка: `model`/`level` из параметров спавна, кастомные переменные —
  дефолтные значения, вычисляемые — в зоне ребёнка), чтение — под
  локом.
  Промпт ребёнка pi-subagents строит в процессе спавнающего
  (`buildEffectiveSystemPrompt`) и передаёт готовой строкой — фоновым
  сериализацией в конфиг шага, файл агента читается внутри скобки.

Свойства лока:

- межпроцессный (сессии живут в разных процессах: раннеры, отдельные
  окна pi); реализация — mkdir-лок или библиотечный, суть — файловая
  блокировка;
- повторно-входимый для одного процесса: параллельные вызовы read в
  одной реплике модели целятся в общие файлы и не должны глушить друг
  друга (счётчик глубины по пути);
- маркер владельца с временем и сброс протухших локов: прерванный ход
  может не дать `tool_result` (гарантия точки снятия при abort —
  сверить по коду pi, `tool_result` или `tool_execution_end`);
- владение ограничено таймаутом.

Разделение нагрузки: чтение тел скилов отдаёт содержимое из файла
зеркала под локом; отдельного механизма «отдать из памяти без лока»
нет — frontmatter скила идёт мимо read tool, частичное покрытие не
оправдывает второго механизма.

## Роль — динамический партиал

Роль не существует как понятие движка. AGENTS.md подключает текст роли
одной строкой:

```text
{{> (concat "roles/" role ".md")}}
```

Значения `role` — имена файлов без расширения, список порождается
shell-командой; добавление роли сводится к созданию файла. Диспетчер
`{{#if (eq role "x")}}…` остаётся легальной, но не рекомендуемой
формой. Линт резолвит имя динамического партиала по конечной области
значений переменной: для каждого значения `concat` обязан дать имя
существующего партиала.

## Точка вставки — декларативная

Расширение ничего не дописывает в промпт. Где подключать роль или
любой другой контент, решает автор AGENTS.md партиалом.

## Субагенты

Требование: шаблоны полноценно разворачиваются в дочерних сессиях
субагентов — иначе задача шаблонизации теряет смысл. Дети получают
расширение через реестр обязательных расширений
(`registerRequiredChildExtensions` на `sessionId` сессии, обязателен
для всех её дочерних сессий) — это цена механизма.

Запуски, не способные грузить расширения (внешние CLI-агенты,
machine-размещения, herdr-дети — панели, спавн демоном), шаблоны не
разворачивают. Запуск не валится (`requireForAllRunners` не
включается): файлы не битые — зеркала остаются последним
отрендеренным текстом, контекст связный (см. «Провал рендера»),
ребёнок получает его как есть. Политика — best effort: расширение
старается довести до пользователя, что он входит в запуск, где
разворачивание шаблонов не сработает; сознательно обходить такие
сценарии — решение пользователя.

Каждая сессия рендерит общие зеркала своим view под локом:
переключение зеркал между сессиями — штатное состояние, каждое
чтение под локом получает вариант своей сессии. Дочерняя сессия не
получает переменных родителя: свои `model`/`level`, свои сессионные
переменные. Роль — частный случай сессионной переменной: детская
сессия стартует с её дефолтным значением, механизм инициализации
сессии в ней отрабатывает как в любой сессии (расширение присутствует
обязательно). Чему равны дефолтные значения переменных — решение
пользователя в конфиге и шаблонах: пустое, непустое или зависящее от
состояния мира (в т.ч. env `PI_SUBAGENT_CHILD`). Механизм детекции
дочерней сессии расширению не нужен и не вводится
(research-child-detection.md).

## Провал рендера

Зеркало получает потребителю либо корректный отрендеренный текст,
либо прежний успешный (кэш = содержимое зеркала и штамп), либо не
получается вовсе — сырых тегов в промпт не бывает.

- провал рендера файла — зеркало не переписывается, предупреждение
  называет источник и причину;
- зеркала нет и рендер не удался: файла для потребителя нет — контекст
  выпадает из промпта, скил выпадает из списка, команда промпта не
  регистрируется, чтение скила даёт ошибку инструмента; предупреждение
  называет причину. Блокировать старт сессии расширение не может и не
  пытается: сигналом служит громкое предупреждение;
- битый `handlebars.json` — view не строится, перересовка не
  происходит (прежние зеркала остаются), предупреждение называет
  причину;
- отсутствие значений `model`/`level` — ошибка расширения,
  предупреждение, перересовка не происходит.

## Линт

Легальные формы: `{{#if (eq v "x")}}`, `{{#if (in v "a" "b")}}`, те же
с `{{#unless}}`, `{{else}}`, интерполяция `{{v}}`, партиалы
статические и динамические (`concat` из литеральных сегментов и
переменных), комментарии.

- необъявленная переменная — ошибка; переменная без списка значений
  объявлена и в интерполяциях, и в сравнениях легальна (литералы для
  неё не проверяются);
- литерал вне списка значений — предупреждение (список может быть
  устаревшим); уровень вне набора уровней мышления — предупреждение;
- динамический партиал по переменной без списка значений — ошибка
  (резолвить нечем);
- синтаксис шаблона во frontmatter разрешён (frontmatter рендерится,
  YAML проверяется после рендера);
- статический партиал — существование файла; строковая форма имени
  подчиняется тем же правилам, что форма-путь (без `..`, без
  абсолютных и обратных слэшей); динамический партиал — существование
  имени для каждого значения переменной из конечного списка.

Линт идёт при старте и при сверке источников; результат —
в предупреждения UI.

## Записи сессии и resume

Смена переменной — запись `customType: "var"`, payload `{name, value}`.
Resume — последнее значение каждой переменной по её записям сверх
машинных значений конфига; `model`/`level` восстанавливает сам pi.
Старт новой сессии — машинные значения, переопределения с нуля. Записи
старого формата (`customType: "role"`) игнорируются.

## UI

`/var` — меню переопределяемых переменных (вычисляемые read-only в меню
не попадают); `/var <имя>` — меню значений; `/var <имя> <значение>` —
прямая установка. Статусная строка показывает переопределения сессии
компактно. `cycle` и Ctrl+R из расширения roles не переносятся.

## Миграция

- `roles.json` → `handlebars.json`: `default` и `cycle` уходят,
  появляется `vars`; стартовое значение роли — `current` переменной
  `role`;
- источники переименовываются в `X.template`: глобальный
  `AGENTS.md.template` со строкой
  `{{> (concat "roles/" role ".md")}}`, `roles/**` — без изменений
  (только источник партиалов), `skills/**`, `prompts/**` и `agents/**` —
  свои файлы с `.template`;
- статические партиалы: имена путями от корня
  (`{{> tests.md}}` → `{{> roles/snippets/tests.md}}`);
- генерируемые `X` добавляются в `.gitignore` проектов;
- пакет `pi-roles` переименовывается (пакет `pi-handlebars`, §5),
  правится `settings.json`; `roles/materialized/` удаляется;
- код ядра (движок `vars`/`render`) переносится из экспериментального
  форка в пакет расширения; форк не нужен.

## План реализации

Работа идёт в пакете расширения. Зоны:

- **A. Движок** — `vars` (схема конфига, вычисление, окружение команд,
  каноническая сериализация) и `render` (грамматика, линт, партиалы,
  рендер) плюс тесты. Готов в форке, переносится как есть.
- **B. Лок-протокол и точки потребления** — штамп свежести, лок
  (межпроцессный, повторно-входимый, сброс протухших), скобки
  `tool_call`/`tool_result` (read и спавн), рендер + `reload` вокруг
  загрузки, пересчёт view по событиям.
- **C. UX и записи** — `/var`, статусная строка, записи `"var"`,
  resume, игнор записей `"role"`.
- **D. Миграция и документация** — конфиг, источники `.template`,
  `.gitignore`, settings.json, README/TESTING.

Проверка: тесты пакета (конвенции форка не применимы — форк закрыт;
тесты ведутся в стиле существующих тестов пакета), `probe`-сценарии
живого рендера; критерии приёмки пакетов — в спеках.

## Что не в этой итерации

- Herdr/machine-дети (принято, §16).
- Шаблонизация пакетных ресурсов и тем.
- Листание переменных (наследник cycle).
