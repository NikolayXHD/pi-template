# Интервью — 21 roles: условные сниппеты штатными механизмами

## 1. Экранирование в Mustache

**@NikolayXHD:** можно ли не трогать точки — escaping, аналог raw string
литерала из Python?

**@pi-agent:** Нет. Имя тега mustache режется на каждой точке
(`name.split('.')` в mustache.js), бэкслэш не спецсимвол: проверено на
4.2.0, `{{#model.gpt\-4\.1}}` ключ `gpt-4.1` не находит. Аналога
raw-string литерала в языке нет. Слэш в имени секции запрещён парсером
(`/` — сигил закрывающего тега). Обход для точек — вложенная карта
(id режется при построении view, в шаблоне дословно), но для слэша
обход заставляет переписывать id в каждом шаблоне.

## 2. Выбор движка

**@NikolayXHD:** mustache не годится как язык общего применения
(дефект спеки, не реализации; больнее всего запрет `/`), альтернатива?

**@pi-agent:** Handlebars — точное надмножество написанного синтаксиса.
Проверено на живом движке: строковое сравнение
`{{#if (eq model "gpt-4.1")}}` (хелпер `eq` регистрируется кодом),
`{{^x}}`, `{{> x.md}}`, потребление standalone-строк совпадает с
mustache байт в байт; экранирование сегмента квадратными скобками
даёт вербатим-адресацию — `{{#model.[deepseek/deepseek-flash]}}` и
`{{#model.[gpt-4.1]}}` работают с плоской картой (совпадение, не
совпадение, инверсия). **Решение:** переходим на Handlebars; view —
плоские карты `model` и `level`, истинный ключ в каждой — текущее
значение; в шаблонах скобочная запись, при необходимости `eq`/`ne`
и `{{else}}`.

## 3. Материализация

**@pi-agent** (предложение, отозвано): коммитить текущий срез —
плоские `roles/materialized/<роль>.md` по текущей паре.

**@NikolayXHD:** идиотское предложение — файл глобальный.

**@pi-agent:** согласен, снимаю: содержимое — функция пары конкретной
сессии, а файл один на машину; сессии затирают друг друга, коммит
фиксирует не состояние репозитория, а то, чья сессия прошла последней.
В задаче 18 коммит работал, потому что дерево было функцией только
входов. Исправленный вариант (ожидает подтверждения): рендер —
сессионное состояние, живёт в каталоге сессии
(`sessionManager.getSessionDir()`, API проверен) — один файл на роль,
атомарная замена одного файла (черновик-каталог и разбор оборванной
подмены умирают); запись сессии `path` указывает туда, рядом в записи
лежит пара; глобальное `roles/materialized/` исчезает вместе с
коммитом; «другая ситуация» — CLI на stdout по явной `--model/--level`.

## 4. Материализация как поверхность решений (решение)

**@pi-agent:** дерево в git — не срез сессии, а полная поверхность
решений шаблонов: упомянутые в шаблонах модели и уровни извлекаются из
AST, `make materialize` без аргументов рендерит все роли во все
различимые области (`roles/materialized/<роль>/<модель>/<уровень>.md`,
`_other`/`any` для дополнений); перечисление выводится, не
поддерживается руками; рантайм дерево не читает и не пишет, сессия
кладёт в запись `{name, model, level, text}`; probe держит инвариант
«перегенерируй в памяти и сравни с деревом».

**@NikolayXHD:** да, это достойный вариант.

## 5. Условие «модель одна из ...» и диалекты (решение?)

**@pi-agent:** `{{#if (in model "model_foo" "model_bar")}}` — хелпер
`in` рядом с `eq`; проверено. Попутно вскрыто: скобочная карта и
хелперные сравнения — два диалекта, молча конфликтующие
(`{{#level.high}}` на строковом view рендерит пустоту без ошибки).
Предложение: унифицировать на хелперах — view строки
`{model, level}`, словарь `eq`/`in`/`unless`/вложенность, извлечение
литералов для materialize однородное, `{{model}}` печатает id; цена —
многословнее частый случай «модель совпала».

**@NikolayXHD:** да, строковый вариант без сомнения лучше; bool-вариант —
неявный сахар и мусорная идея, мы имеем дело со строками.

**Решение:** view — строки `{model, level}`; условия только через
`eq`/`in`/`unless`/вложенность; materialize линтит и роняет шаблоны
с обращением по второму сегменту под `model`/`level`.

review-1.md, правки вошли в design.md.

- **Восстановление при resume:** провал рендера на resume поднимает

## 7. Автодописывание cycle — баг

**@NikolayXHD:** почему в roles.json дописываются роли? Это не
раздражает, это баг — ломается множество ролей, которые я переключаю
по Ctrl+R.

**@pi-agent:** дописывал `syncCycle` (наследие задачи 18: новая роль
файла сама попадает в список включений). Удалён: `cycle` значит ровно
то, что в нём написано; мёртвые имена пропускаются при листании;
пишут в список только ручная правка и Tab в меню. Заготовка при
отсутствии `roles.json` по-прежнему получает `cycle` из каталога —
один раз при первом старте. Роль, дописанную багом, из живого
`roles.json` убрал.
