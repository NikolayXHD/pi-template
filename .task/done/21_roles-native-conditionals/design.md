# Дизайн — 21 roles: условные сниппеты штатными механизмами Handlebars

## Цель

Снести алгебру записей (ключ `template_variables` в `roles.json`,
области по модели и уровню, флаги сужения): условность сниппетов
выражается штатными механизмами движка шаблонов — сниппет сам
оборачивает содержимое в условие над текущей парой «модель, уровень
мышления». Рендер происходит в память, точный текст роли уходит
в запись сессии. Текст действующей пары записывается в дерево
`roles/materialized/` — кэш того, что реально отправлялось; он даёт
заметность изменений промптов в дифах для используемых пар и
обновляется сам при использовании.

## Термины

- **Сниппет** — файл в `roles/snippets/`, включаемый в роль.
- **Партиал** — тег `{{> имя-файла}}`, подставляющий содержимое файла;
  имя партиала — имя файла в `roles/snippets/`.
- **View** — объект данных, из которого рендерер берёт значения;
  строится расширением на каждом применении роли.
- **Условие** — блок `{{#if ...}}` или `{{#unless ...}}` над вызовами
  хелперов сравнения.
- **Линт** — проверка шаблона по AST до рендера; нарушение — ошибка,
  а не тихое отклонение.
- **Поверхность решений** — разбиение пространства пар «модель, уровень»
  на классы так, что внутри класса текст каждой роли постоянен; классы
  задаются истинностью всех сравнений во всех шаблонах.
- **Реестр моделей** — список моделей текущей сессии
  (`ctx.modelRegistry.getAll()`).
- **Снапшот входов** — слепок mtime и размера входных файлов для
  отслеживания правок между ходами.
- **Запись сессии** — строка JSONL в файле сессии; расширение пишет
  записи с `customType: "role"`.

## Движок

Рендерер — Handlebars (пакет `handlebars`), замена mustache.
Роли и сниппеты сегодня содержат только партиалы `{{> имя-файла}}`;
этот синтаксис валиден в Handlebars. Потребление standalone-строк
(тег на отдельной строке съедает перевод строки) совпадает с mustache —
проверено на живом движке: `A\n{{#if c}}\nB\n{{/if}}\nC` рендерится
в `A\nB\nC` обоими.

## View и словарь условий

View — две строки:

```json
{ "model": "deepseek/deepseek-flash", "level": "high" }
```

Хелперы расширения — чистые сравнения, регистрируются при загрузке:
`eq(a, b)` — равенство строк; `in(a, v1, v2, ...)` — «a — одно из».

### Грамматика тегов

Легальная форма одна; всё вне её — ошибка линта.

- Условия: `{{#if (eq model "x")}}`, `{{#if (in model "a" "b")}}` и те
  же с `level` и `{{#unless ...}}`. Хелперы `eq`/`in` — только
  подвыражения внутри `if`/`unless`; первый аргумент — путь `model`
  или `level` из одного сегмента; остальные аргументы — строковые
  литералы. `{{else}}` разрешён внутри `if`/`unless`. Вложенные `if` —
  конъюнкция.
- Интерполяция — только `{{model}}` и `{{level}}`; печатают составную
  строку `<provider>/<id>` и имя уровня дословно.
- Партиалы `{{> имя}}`: имя — имя файла в `roles/snippets/`, может
  содержать точку (`{{> task_tracking.md}}`). Запрещены `..`, ведущий
  `/` и обратный слэш — путь уходит в дерево materialized.
- Комментарии `{{! ... }}`.
- Запрещены: голый путь в условии (`{{#if model}}` — условие обязано
  быть сравнением), обращение по второму сегменту пути
  (`{{#model.[x]}}`, `{{#level.high}}`), любые хелперы и блоки кроме
  перечисленных (`each`, `with`, `lookup`).

Линт выполняется на каждом рендере и в материализации; он разбирает
шаблон роли и все её достижимые партиалы, а также все файлы каталога
сниппетов, включая недостижимые.

Причина строкового view: карта истинных ключей не умеет «одна из» и
требует другого представления тех же имён; смешение двух диалектов
рендерится пустотой без ошибки (@NikolayXHD: bool-вариант — неявный
сахар, мы имеем дело со строками). Один легальный стиль делает
нарушение громким через линт.

## roles.json и выбор роли

### Файл

`roles.json` — объект с ключами `default` (непустая строка, имя роли
для старта) и `cycle` (массив строк); прочие ключи — ошибка разбора.
Имена не сверяются с каталогом при разборе: неизвестное имя проявляется
в момент использования — при активации предупреждением
`Роль "X" не найдена в roles/`, при синхронизации `cycle` —
выключением имени из списка.

Файла нет — это заготовка: пустой объект, материализация записывает её
на диск и дописывает в неё `cycle` из каталога ролей — один раз, при
первом старте. Дальше `cycle` не синхронизируется с каталогом: список
значит ровно то, что в нём написано, новые роли в ротацию сами не
попадают; мёртвые имена при листании просто пропускаются. Пишут в
список только ручная правка и Tab в меню ролей.

Битый файл — предупреждение. Недоступны: активация по `default`
(стартовая роль неизвестна), Ctrl+R (порядок `cycle` неизвестен),
Tab в меню (членство неизвестно). Доступны: `--role`, `/role <имя>`,
меню `/role` без Tab — рендер роли от конфига не зависит.

Механика `cycle` — `roleNames`, `resolveCycle`, `setCycleMembership`,
`syncCycle` — живёт в `config.ts`: это слой выбора роли, а не
материализации. `serializeConfig` перестаёт писать
`template_variables`.

### Порядок выбора роли

1. При `reload` и resume — имя из последней записи сессии `role`.
2. Иначе флаг запуска `--role`.
3. Иначе ключ `default` из `roles.json`.

Роль несёт только основной агент: субагент-процессы (env
`PI_SUBAGENT_CHILD`) не активируют и не обновляют роли.

## Рендер и правило провала

Пара берётся из контекста хода: модель — составная строка
`<provider>/<id>` без разбора, уровень — значение thinking level.
Отсутствие модели или уровня — throw: ход без пары не начинается,
а роль без текста молча оставлять нельзя.

Рендер происходит в память: компиляция шаблона роли с
зарегистрированными партиалами сниппетов. Файлы расширение в рантайме
не пишет.

Провал рендера — ошибка компиляции, нарушение линта, отсутствующий
файл партиала — работает так: предупреждение; активная роль продолжает
нести текст прошлого успеха. Прошлого успеха нет:

- при старте сессии роль остаётся неприменённой — текста в промпте
  нет, статус `role:—`;
- при resume и `reload` текст берётся из последней записи сессии
  `role`; пара в ней может отличаться от текущей, предупреждение
  называет источник текста.

Так сохраняется свойство прежней реализации: перезапуск не сбрасывает
роль из-за временной поломки шаблона, при том что состояние больше
не живёт в файлах.

Правки входов применяются со следующего хода: снапшот входов
(`roles.json`, `roles/*.md`, верхнеуровневые файлы `roles/snippets/`)
сверяется перед каждым ходом; различие запускает пересбор. Снапшот
принимается только при разобранном конфиге — иначе полузаписанное
чтение закрепилось бы и правка не применилась бы никогда.
Предупреждения дедуплицируются по тексту; память о показанных
сбрасывается на `session_start` и при принятии нового снапшота.

## Запись сессии и событие

Payload записи и события `roles:active` — `{name, model, level, text}`,
где `text` — точный текст, отправленный в промпт. Новая запись и
событие пишутся при изменении любого из трёх значений `model`, `level`,
`text` относительно последней записи. Издержка: файл сессии растёт
пропорционально сменам (текст роли — килобайты) — осознанная плата
за самодостаточную историю.

Формирование payload — чистая функция рядом с рендером, чтобы probe
мог проверять её без загрузки расширения.

Breaking change для соседних расширений: sidekick копировал правила
по `path`; потребителям нужно перейти на `text`.

## Материализация по необходимости

Рендер роли отправляется в промпт из памяти и одновременно записывается
в дерево `roles/materialized/<модель>/<уровень>/<роль>.md`: файл назван
ролью, каталоги повторяют действующую пару. Запись делается в момент
применения роли и при смене тройки `(model, level, text)`; если тройка
не изменилась, файл не переписывается. Запись атомарна (временный файл
плюс переименование); провал записи — предупреждение, на промпт он не
влияет.

Свойства:

- дерево — кэш того, что реально отправлялось: никаких заготовленных
  комбинаций и дополнений; пара, которой не было, файла не имеет;
- пары не затирают друг друга: разные пары — разные каталоги;
- правка источников меняет файл действующей пары на следующем ходу —
  `git diff` показывает изменения промптов для используемых пар; файл
  пары, которую не запускали, остаётся прежним до следующего
  использования и обновляется сам;
- модель-каталог повторяет сегменты id: `deepseek/deepseek-flash` —
  каталог `deepseek/deepseek-flash/`; сегменты `.` и `..` отвергаются;
- отдельной проверки свежести нет: кэш обновляется сам при
  использовании пары.

Предупреждения о сомнительных литералах: уровень, не входящий в набор
уровней мышления, — предупреждение в сессии и в CLI (набор статичен);
модель, которой нет в реестре сессии, — предупреждение только
в сессии, в CLI реестра нет. Опечатка создаёт условие, которое никогда
не совпадёт.

Для рендера произвольной пары без сессии — `make materialize
MODEL=… LEVEL=…`; без аргументов команда падает с указанием того,
чего не хватает.

Старое дерево `roles/materialized/default/**` удаляется из
репозитория.

## Инвентарь кода

- `config.ts`: удаляются `VariableEntry`, области, флаги,
  `valueForEntry`, `matchEntries`, `unknownModelReferences`,
  `template_variables` из `serializeConfig`; добавляется строгий разбор
  `{default, cycle}`; переезжает механика `cycle` из `materialize.ts`.
- `render.ts`: удаляется сбор имён секций; остаются компиляция и
  партиалы; добавляются линт AST и извлечение литералов; рядом —
  чистая функция формирования payload.
- `materialize.ts`: удаляются черновик, подмена, разбор оборванной
  подмены, сборка по записям; остаются запись варианта по паре
  и CLI-материализация явной пары.
- `index.ts`: удаляются `resolveVariant` и поля `entry`/`path`;
  остаются выбор роли, снапшот, предупреждения, запись и событие;
  после применения роли и при смене тройки — запись варианта в дерево.

## Миграция

- `roles.json`: убрать `template_variables` — ручная правка, один раз.
- Сниппеты: обёрток нет, всё безусловно; условия добавляются по мере
  надобности.
- `probe.mjs`: переписать. Сценарии: грамматика (таблица отказов
  линта), извлечение литералов и графа партиалов, правило провала,
  восстановление при resume (чистая функция payload), битый конфиг,
  механика `cycle`, запись варианта по паре (путь, атомарность,
  отвержение сегментов `.`/`..`), CLI-материализация явной пары.
- `TESTING.md`: материализация — `make materialize`; наблюдение текста
  по записи сессии; импорт handlebars под загрузчиком pi; сценарии
  битого конфига по политике этого документа.
