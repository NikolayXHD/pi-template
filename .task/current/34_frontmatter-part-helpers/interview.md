# Вопросы: хелферы частей frontmatter

## Решил `@NikolayXHD`

- Владелец `timeoutMs` — наш файл агента, а не файл пакета.
- Промпт чужого агента не дублируется: хелфер отдаёт часть файла, обёртку `---`
  пишет `.md.template`.
- `timeoutMs` живёт в нашем `agents/reviewer.md.template`, а не в файле пакета
  и не в симлинке на него.
- Версии не пинать — ради теста тем более.
- Тесты, которым нужен импорт чужого кода, отменяются: остаются тесты,
  работающие своим ходом.

## Решено `@pi-agent` (по `review-design.md`)

- [x] 1. Имена: `frontmatterKeys` и `bodyAfterFrontmatter`. Термин «include» в
      pi-template уже значит «отрендерить и отлинтовать чужой шаблон»
      (`{{> }}`), а новые хелферы отдают часть файла как есть. Длинные имена
      встречаются в шаблоне по одному разу и окупаются однозначностью
      (`review-design.md`, находка 10).
- [x] 2. Файл без frontmatter — ошибка, и сообщения два разных: «no
      frontmatter» (первая строка не `---`) и «unclosed frontmatter» (обёртка
      не закрыта). Для целого файла есть `{{> }}`.
- [x] 3. Предупреждение на `{{` в срезе — нужно, один раз на имя: цель с чужим
      телом легально содержит `{{`, и человеку полезно знать, что рендер его не
      трогал.
- [x] 4. Имя включения — от корня агент-директории, без `..` и ведущего `/`;
      иначе ошибка линта (резолвер за корень не пускает).
- [x] 5. Срез ключей обрезается по краям от пустых строк (в цели не
      появляется лишняя пустая строка перед собственным ключом), тело —
      `.trim()` по краям, как делает `parseFrontmatter` (находка 20).

## Решено `@pi-agent` (делегировал `@NikolayXHD`)

- [x] 6. Разрез проверяют матрица входов (параметризованный тест, ожидания
      руками) и roundtrip разбором штатного `parseHeader` (`simpleHeaderParser`
      в probe): без правок — разбор собранного равен разбору нормализованного
      оригинала; с вставленным ключом — все исходные ключи и наш в
      frontmatter-части, наша строка ниже, тело на месте. Чужой код не
      импортируем — сверки с парсером pi-subagents нет, расхождения
      задокументированы, потребителя проверяет ручной сценарий (отказ
      `@NikolayXHD` от импортов и пинов; находки 13, 21, 22 сняты выбором
      тестов).
- [x] 7. Отказ «файла нет» — как у `{{> }}`: статическое имя без файла —
      ошибка линта, динамическое — предупреждение линта и ошибка рендера для
      выбранного значения (находка 16).
- [x] 8. Предупреждение о `{{` — для обоих хелферов (ключи и тело), текст с
      именем хелфера, одинаковое — один раз (находка 15).
